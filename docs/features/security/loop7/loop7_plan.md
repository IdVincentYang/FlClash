# Loop 7：Android 整体验收与上网安全结论

本轮验证各阶段保护在同一实际 Android 产物中一起生效，并回答该版本是否适合用于上网、剩余风险在哪里。以[共同安全目标](../security_requirements.md)为验收依据，当前维护阶段方向，review 确定后再拆 tasks。

## 需求与正向价值

用户需要一个能正常联网、自动刷新订阅、判断常用站点可达性并保存本地 bug 证据的客户端，也需要确认软件行为、依赖与安装包可信。

目标是将修复、实际配置/出口、构建输入、最终包和剩余风险对应起来，支持可理解的使用决定。正常服务收到必要请求、接受的 DIRECT/DNS 和官方组件均按已确定的用途与信任条件验收。

## 风险与不验收的后果

| 集成风险 | 为什么单轮不足 | 不处理时可能发生什么 |
| --- | --- | --- |
| 代码与 APK 不一致 | 合并 manifest、SDK、release 配置、缓存、签名和资产共同参与产物 | 修复没进入安装包，删除的采集 SDK 又由传递依赖引入 |
| 跨阶段冲突 | 下载/配置/DNS、代理认证、Geo 更新及报告存储互相影响 | 一处保护被另一处绕过，或正常功能失效迫使用户放宽边界 |
| 故障与状态过渡 | 启动、VPN 撤销、后台、重连、IPv6 及取消改变连接条件 | 非预期出口、额外请求、错误保护提示或证据丢失在静态审查中遗漏 |
| 证据与版本漂移 | 扫描、签名、短时观察各只覆盖部分；上游更新会改变对象 | 将局部通过写成全局安全，或用旧证据说明新包已验证 |

## 验收思路

- 绑定主仓库/核心提交、锁定依赖/数据、实际工具、环境、API/ABI 范围、APK 摘要、签名及符号。核对实际最终包中的库、资产、权限和初始化，不以源码或 debug 配置替代最终交付配置。
- 在受控 Android 环境验证正常上网、自动刷新、常用站点诊断、所需导入/共享/备份/恢复、Geo 更新和本地报告，形成连贯使用闭环。
- 同时验证合法行为和拒绝非预期行为：接受的代理/DIRECT/DNS 正常工作，隐藏上传、无关数据/接收方、秘密日志、未允许访问和出口变化被限制。
- 覆盖启动、暂停、失效、取消、重试、跳转、VPN 撤销和恢复等条件，依据选择的策略判断结果。全设备故障阻断仅在另行选定时验收，不能把允许直连一律计为失败。
- 结合源码、产物与真实连接/接收端观察核实 SDK 和核心的实际行为。使用合成订阅、凭据、二维码和报告，优先本地目标；区分系统噪声和应用行为，原始用户流量及秘密不发到外部测试服务。
- 对基线及新增发现分别给出结果、条件、证据强度和复核入口。确认关键回归能发现保护丢失，跨阶段问题返回所属阶段修复，避免在验收中悄悄放宽需求。
- 记录正式验收结论与稳定复现入口；原始日志/抓包/包/符号留本地，重复构建沿用[构建指南](../../../development/android_build_guide.md)，不为每次编译增加文档。

## 收益与代价

收益是发现跨层绕过与功能退化，最终结论对应用户实际安装的版本。代价是需要受控设备、代表性配置和故障覆盖，覆盖不足会限制能给出的结论。

每项网络活动按用途及策略评价，安全性与可用性共同验收。短时未观察到外发只能说明当时条件，不能单独证明隐藏行为不存在；关键未验证边界需要补证或限制适用范围。

## 依赖、完成方向与使用结论

- 接收 [Loop 1](../loop1/loop1_plan.md)、[Loop 2](../loop2/loop2_plan.md)、[Loop 3](../loop3/loop3_plan.md)、[Loop 4](../loop4/loop4_plan.md)、[Loop 5](../loop5/loop5_plan.md)、[Loop 6](../loop6/loop6_plan.md)实际交付；发生输入变化后重新核对相关路径。
- 完成时正常用途和关键拒绝边界均有实际证据，受测对象与最终包对应；失败、跳过、未验证和适用限制明确说明。
- 使用结论明确回答：是否仍有隐藏收集/额外上传、非预期改道、凭据泄漏、来源未知执行内容或可达重大缺陷；发生在哪个组件、何时触发、有什么影响及缓解，是否阻止当前版本使用。
- 将发现区分已修复、已证实不影响、已缓解有剩余风险、未解决和未验证。重大未解决风险或关键证据缺口不能通过“已告知”转为安全通过。
- 结论仅覆盖受审版本和条件；说明正常代理/DNS/订阅/目标网站的可见范围及第三方、操作系统信任，避免承诺匿名或零风险。
- 按[官方同步约定](../../../../CONTRIBUTING.md)保留受影响回归和冲突理由，同步后重新绑定变更范围。设备安装、改系统路由、APK 发布或对外发送证据使用相应授权。
