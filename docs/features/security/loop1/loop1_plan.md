# Loop 1：隐私外发与请求出口

本轮形成 Android 客户端可体验的隐私闭环：启动和后台运行不产生未经功能授权的可选外发；用户能知道请求目的、接收方和出口；代理不可用时敏感请求停止；订阅与备份凭据不会进入无关接收方或诊断日志。覆盖[审计基线](../android_security_baseline.md) A-01、A-02、A-03、A-15。

具体任务、负责人、依赖和验收记录统一维护在 [loop1_tasks.md](loop1_tasks.md)。当前交付为任务规划，应用行为尚未整改；下表区分已确认需求与待 review 建议，局部决定不代表整轮已批准实施。

## 用户场景与范围

- 新安装、升级、恢复备份、启动和进入仪表盘时，先完成隐私状态加载，再决定是否允许后台请求。
- 保留常用服务的可达性诊断，按用户选择的目标、出口与刷新方式检查；IP/质量查询的去留单独决定。停用目标后取消请求与重试。
- 保留订阅自动刷新及手动刷新，按逐订阅开关、周期、目标和出口策略执行；网络不可用时等待/失败，不静默改变为未授权直连。远程脚本、主动检查更新和 WebDAV 遵守对应请求边界。
- 删除自动应用更新检查的启动、后台调度与设置入口；旧开关不重新触发自动查询。
- 无代理配置、核心启动失败、VPN 撤销、SSID 排除、切换节点或网络中断时，界面给出准确状态，旧任务不借新的路由继续外发。
- 扫码和读取二维码图片在设备上完成，不产生统计或诊断上传；崩溃后既能安全启动，也能在本地找到可获取的异常堆栈、系统 trace/tombstone 与版本信息。

本轮包括应用自身请求、Go 包装层的 IP/服务探测、原生 SDK 初始化与后台任务。导入配置的信任和全设备流量/DNS 策略归 [Loop 2](../loop2/loop2_plan.md)，外部 Intent 和存储/备份保护归 [Loop 3](../loop3/loop3_plan.md)，依赖漏洞归 [Loop 4](../loop4/loop4_plan.md)，工具与工件来源归 [Loop 5](../loop5/loop5_plan.md)，Geo 数据真实性归 [Loop 6](../loop6/loop6_plan.md)。本轮为这些功能提供请求授权、传输和脱敏边界。

## 产品选择与 review 状态

这里是本轮产品选择的唯一维护位置。任务文档引用这些选择；后续决定更新本表及受影响验收，不另建平行策略清单。功能是否需要由使用需求决定，外部请求是否安全由数据、接收方、传输和出口判断。

| 选择 | 行为或建议 | 影响与 review 重点 | 状态 |
| --- | --- | --- | --- |
| 公网 IP 与归属地 | 建议保留出口识别能力，减少到明确选择的 HTTPS 来源；归属地/ASN 优先由可信本地数据推导 | 可核对某条探测路径的出口和地区，不能证明所有应用都无泄漏；接收方会看到请求源 IP | 去留及触发方式待决定 |
| IP 质量 | 提供住宅/数据中心、代理/Tor、滥用标记等辅助信息；建议默认不自动向多家服务查询，保留手动或删除待决定 | 评分不代表隐私安全；查询会把被查 IP 交给额外的第三方 | 待决定 |
| 常用站点诊断 | 保留用户需要的可达性/延时检查；按目标和频率配置，使用匿名最小请求。地区/Premium/解锁检查与基础可达性分别展示 | Google/YouTube 是明确使用需求；不附浏览器登录 Cookie、订阅或代理凭据，不默认遍历无关平台 | 保留需求已确认；目标、频率与展示细节待细化 |
| 自动应用更新检查 | 删除启动/后台自动检查及开关；旧 autoCheckUpdate 不生效 | 仍可通过用户主动操作关注版本，未扩大到删除手动检查 | 删除已确认 |
| 订阅自动刷新 | 保留自动刷新、逐订阅开关与周期，迁移保留已有设置；完成目标/出口状态加载后执行，失败保留旧配置并有限重试 | 订阅服务器需要收到令牌，重点避免其它接收方、日志泄漏和未告知的真实 IP 暴露；节点失效时的直连例外需按订阅明确配置 | 保留已确认；出口例外细节待 review |
| Firebase 与本地诊断 | 删除 Analytics/Crashlytics；保留本地启动恢复并新增崩溃证据保存，详见下节 | 不再远程统计/上报；本地证据可用于修复 bug | 删除 SDK、保留本地诊断已确认 |
| 扫码 SDK | 优先采用可审查源码、无网络采集的离线二维码实现；无法证明关闭采集有效的 SDK 不纳入本轮完成产物 | 保留相机和图片扫码；新依赖记录源码、许可证、版本及能力 | 方案待 review |
| 请求出口 | 敏感请求默认要求明确代理出站；不可用则等待/失败。首次导入或节点失效时确需直连，按目标、用途与有效期显式允许，可为已启用自动刷新预先设置有限例外 | 本机 mixed-port 不证明最终非 DIRECT；不能以安全改造为由静默取消自动刷新，也不能自动扩大直连授权 | 具体策略待 review |
| 传输与可见性 | 外部请求采用 HTTPS 和有效证书；重定向重新检查接收方/出口，限制凭据及数据转发；常规日志脱敏 | 不安全 HTTP/证书配置需处理；hideIp 为显示遮罩，外部查询另设控制；原始系统崩溃证据按下节私有保存 | 实现细节待 review |

“代理出站”的验收必须区分应用接入核心、核心最终选中的出站和 DNS 实际路径。Loop 1 控制自身请求的出口及回退；全设备 VPN 的阻断、恶意配置和 DNS 泄漏结论由后续 loop 验收。外部浏览器打开链接需告知移交行为，应用不能承诺控制浏览器的网络出口。

## 本地崩溃恢复与证据

当前 [BootRecord](../../../../lib/common/boot_record.dart)保存启动阶段、配置 ID 和连续失败次数；[BootGuard](../../../../lib/common/boot_guard.dart)据此跳过自动启动或解除当前配置选择，避免启动崩溃循环。[GlobalState](../../../../android/common/src/main/java/com/follow/clash/common/GlobalState.kt)目前只读取退出原因、时间和描述。这些恢复记录不包含完整 dump，也不能代替异常报告。

新增要求是保存在本机可获得的 Dart/Java 异常堆栈、Go/Rust/native 崩溃线索、ANR trace/原生 tombstone，以及对应的应用/核心版本、ABI、进程与 Build ID。匹配的 R8 mapping、可用原生符号和必要 Dart 符号文件由同次构建在本地保留，便于还原堆栈。完整进程内存镜像不作为默认采集内容。

Android API 30 起提供退出记录和可用的 ANR trace，API 31 起可读取本应用原生 tombstone；系统循环缓存可能已覆盖内容，trace 可为 null。低版本/缺失 trace 必须记录实际能力和失败原因，不能承诺每种崩溃都能生成完整报告。[Android API 说明](https://developer.android.com/reference/android/app/ApplicationExitInfo#getTraceInputStream())、[原生 tombstone 说明](https://developer.android.com/ndk/guides/debug#tombstones)。

原始系统报告可能带内存片段，视为敏感本地证据：保存于应用私有且排除系统自动备份的目录，例如 noBackupFilesDir；不自动上传、不加入 WebDAV 备份或常规日志导出。面向查看/导出的摘要脱敏；用户明确选取的原始证据保留原内容，不声称可以完全脱敏。提供本地查看、选择保存/导出和删除，容量及轮转策略在任务设计时明确，不因启动恢复而清掉 bug 证据。[系统备份排除规则](https://developer.android.com/identity/data/autobackup)。

## 完成条件与接续

1. 外发清单覆盖 Dart、Go 包装层和原生 SDK；每条路径有明确接收方、触发条件、数据、授权与出口要求，未知项不标记通过。
2. 上述用户场景在功能授权、取消、升级迁移和失败路径上形成闭环；功能可用性与安全边界均有验证。
3. Android 最终产物、真实请求出口和敏感日志通过任务文档中的验收；SDK 移除以依赖/产物核对和运行观察共同确认。
4. 各任务通过评审、按授权合入 security/android，验收记录绑定实际源码与 APK；未通过或未验证项明确交接，不以任务数量代替完成判断。

官方同步要求：遵循 [CONTRIBUTING.md](../../../../CONTRIBUTING.md)，保留按行为划分的小提交和可复用的安全回归用例；上游修改相关入口后重新运行受影响验收。共享生命周期由现有 ServiceState 和路由状态负责，避免另建一套服务状态或大范围改写上游结构。
