# Loop 1：应用联网用途、敏感数据与本地诊断

本轮让订阅刷新、站点诊断等应用自身联网符合用途，处理隐藏采集、额外传输和凭据泄漏，同时保留本地故障恢复与 bug 证据。依据
[共同安全目标](../security_requirements.md)，对应[审计基线](../android_security_baseline.md)
A-01、A-02、A-03、A-15。阶段方向已确认，具体未决选择仍由下表维护；[任务清单](loop1_tasks.md)按删除、修改、增加安排，
并维护指派、执行状态和验收入口。
当前用途、执行归属与覆盖限制由[联网用途清单](../android_network_inventory.md)维护；未知、失败及未验收范围分别保留。

实际推进优先考虑日常上网风险；用户决定暂缓的任务及恢复条件由[任务清单](loop1_tasks.md#执行顺序与记录约定)维护。暂缓不等于风险已解决，
也不要求其它独立任务等待；阶段完成与最终使用结论保留尚未覆盖的边界。

## 需求与正向价值

订阅自动刷新保证节点和规则持续可用；Google、YouTube 等站点诊断帮助判断实际使用服务的可达性与出口。本地崩溃证据用于修复 bug，
启动恢复避免应用陷入失败循环。需要保留这些用途，并限制每条请求和报告中包含的数据。

本轮以用途、接收方、数据、触发条件和实际出口作为判据。所选服务收到必要请求属于功能正常行为；软件额外收集、复制秘密或偏离接受的路由需要整改。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| IP/归属地与质量 | 单一 HTTPS trace 与显式分类；hideIp 只管显示 | 必要 IP 披露；新增来源/自动触发可能扩大范围 |
| 常用站点诊断 | 不附浏览器 Cookie；基本与地区/解锁结果分开 | 无关标识/目标/频率超出用途；误解结果 |
| SDK 初始化 | Firebase/ML Kit 已删除；本地 ZXing，剩余初始化另核对 | 依赖回流或条件外发遗漏 |
| 生命周期与出口 | Disclaimer 已删；运行/暂停/故障及 Direct 仍按用途授权 | 非预期回退；不能将所有直连视作泄漏 |
| 认证、跳转和日志 | URL 可含令牌；部分日志含 URL，WebDAV 有跳转 | 秘密入日志，认证/备份体到错误目标 |
| 恢复与报告 | 已有有限私有持久报告、受控摘要和显式原文导出 | 原文秘密、云提供方、符号/报告缺失 |

原审计事实保留在[审计基线](../android_security_baseline.md)；上表描述当前行为及剩余风险。
SDK 依赖、厂商披露和源码线索分别形成证据，不能据依赖名称断言二维码图片、订阅或用户访问内容被上传。

本表维护产品决定与当前落地入口；未闭合验证和后续选择按各主题契约及任务记录区分。

| 功能 | 已确定方向 | 当前入口与剩余边界 |
| --- | --- | --- |

| 订阅自动刷新 | 保留逐项开关/周期及自动/手动刷新，不重复询问 | 已交付用途/出口/取消边界；普通 TLS/跳转/日志仍见 T04/T05 |
| 自动应用更新检查 | 删除启动/后台自动查询及开关；保留用户主动检查 | 删除已交付，手动版本查询与浏览器移交分别核对 |
| Firebase | 删除 Analytics、Crashlytics 及初始化、构建上传路径 | 删除已交付，最终包及依赖回流检查见用途清单 |
| 本地 bug 证据 | 保留启动恢复，保存可获取异常及系统报告/dump | [报告契约](../crash_reports_design.md)与[使用指南](../crash_reports_guide.md)维护覆盖、容量/期限及导出限制 |
| 公网 IP/归属地 | 保留，默认手动，可明确启用前台仪表盘自动刷新；旧用户默认不开启 | 单一 Cloudflare HTTPS trace，国家取同一回答，不自动换源；契约见 [IP 查询设计](../ip_lookup_design.md) |
| IP 质量 | 保留详情中的显式单次分类，显示 IP、进入详情和预览不触发 | 用户已确认改用单一 Proxycheck HTTPS v3 匿名查询；拒绝／限额时失败，不直连或换源；见 [IP 查询设计](../ip_lookup_design.md) |
| 扫码 | 保留相机/相册，以本地 ZXing 替换 Android ML Kit | 已交付；设备/相册提供方限制见[长期契约](../qr_scanning_design.md) |

## 解决思路

### 核实应用自身联网的完整范围

用户已明确删除 Disclaimer：首次启动不再要求同意／退出，工具页移除该入口，接受状态及其专属请求 gate／刷新 listener 一并删除；
旧配置中的接受键按未知字段忽略。LICENSE、版权及第三方许可证保留。请求运行／停止、路由、来源、取消与订阅刷新资格继续由原机制执行，
启动完成、started 和 appVisible 沿用现有刷新触发。IP 功能、自动范围和来源按上表独立决定。

沿现有 Dart 请求、Go 包装层探测、核心内部下载及原生 SDK 边界盘点用途，包含初始化、后台、重试、跳转和独立客户端。对 SDK 不仅检查公开 API，
也核对实际初始化组件及启用条件。

应用请求按接受的出口策略执行。允许 DIRECT 的用途保持可用；需要代理的用途遇故障按明确策略等待或失败，避免静默降级。首次导入和订阅恢复可以需要直连，
要明确它们的用途与接收方。保护不能只依赖 UI 已初始化或一个本机 PROXY 字符串。

优先在现有请求边界复用校验与调度；Dart、Go、SDK 不能共享同一路径时，各自落实相同要求。状态变化、取消和迟到结果按已有生命周期权威处理，
防止旧任务继续执行已撤销的用途。

### 保留刷新与诊断，收窄数据和接收范围

只向订阅服务交付必要认证；验证服务身份，处理跳转时分别检查 URL、认证头和请求体。下载失败保留旧配置，下载成功后的内容接受归 Loop 2。

Google/YouTube 等诊断保留，并显示受测用途与实际结果。基础连通性、地区/Premium/解锁分别表达；单次诊断只证明该请求，
不能推导全部浏览流量受保护。

IP 查询和分类按[当前契约](../ip_lookup_design.md)使用单一 HTTPS 来源及相应手动/自动资格；新增来源需重新判断披露范围。
日志、错误信息和请求跟踪仍需避免复制认证秘密，T05 暂缓风险不因 IP 局部保护而视作解决。

### 删除已拒绝采集，保留可用的本地证据

删除 Firebase 的实际依赖、自动初始化、设置和构建上传，并核验最终 APK。对其它 SDK 分别检查用途与行为；
不能控制的额外采集需替换实现或移除对应依赖，保留所需产品能力。

保留启动恢复，持久保存可获取的 Dart/Java 异常、Go/Rust/native 线索及系统 ANR/原生报告。版本、进程、ABI、Build ID
与匹配符号便于定位 bug；说明报告缺失、系统缓存和低 API 的实际限制，不承诺每次都有完整 dump。
启动恢复的有效分类、配置保留、验证入口和设备限制由[恢复契约](../boot_recovery_design.md)维护；
任务交付与历史证据入口由[任务清单](loop1_tasks.md#l1-t10-修改本地启动恢复与证据处理边界)维护。

本地证据的当前能力及验证／设备边界见[报告契约](../crash_reports_design.md)。
常规日志/报告尽量减少秘密；需要用于修复的原始系统报告单独私有保管，排除自动上传和备份，导出时可明确选择原始内容。完整进程内存镜像的范围另行设计，
恢复流程保留已有证据。存储与备份规则归 Loop 3，符号对应关系归 Loop 5。

## 收益、代价与阶段边界

收益是减少超出用途的收集及凭据传输，同时保持正常刷新、网络排查和 bug 修复能力。代价是盘点跨语言请求、适配 SDK 和报告生命周期；
出口限制需要兼顾首次导入、节点失效与旧配置迁移。

本轮不强制所有请求经代理，也不因站点正常看到出口 IP 就删除诊断。TLS 身份验证、认证范围与日志保护对直连和代理均适用。
IP 和扫码沿用已确认的保留方向与当前主题契约；局部保护不代替通用请求和全应用验收。

配置和业务 DNS/路由由 [Loop 2](../loop2/loop2_plan.md)负责；本机数据由
[Loop 3](../loop3/loop3_plan.md)负责；漏洞、组件来源和 Geo 发布内容分别归
[Loop 4](../loop4/loop4_plan.md)、[Loop 5](../loop5/loop5_plan.md)、
[Loop 6](../loop6/loop6_plan.md)。核心/SDK 中新发现的外发不能因不经过 Dart 就遗漏，按用途关联所属阶段。

## 完成方向与官方同步

- 保留项正常工作、删除项不再进入或初始化于最终产物；应用外发符合用途、接收方、数据和接受的出口。
- 启动、暂停、故障、取消、重试和跨源跳转不会泄露秘密或绕过用途限制；直连和代理两种已接受路径均有验证。
- 本地可获取 bug 证据跨启动保留，原始报告未随普通备份/日志自动外传。
- 验证结合源码、最终包与受控观察，范围和限制交给 [Loop 7](../loop7/loop7_plan.md)；具体交付、依赖和验收入口见
  [任务清单](loop1_tasks.md)，未决选择先明确再实施相关改动。
- 按[官方同步约定](../../../../CONTRIBUTING.md)保持窄改动和现有状态所有权；同步后复核采集依赖、请求策略与本地报告是否被改变。
