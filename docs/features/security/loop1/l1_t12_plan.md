# L1-T12 报告管理与选择导出 Plan

任务见[清单](loop1_tasks.md#l1-t12-增加本地报告管理与选择导出)，M1 评审、D-02 实施。
输入基线为 `9d8393532986819e4b107f1e050f8a24fdf64a80`。design_v1 已获 M1 通过，实施与验证进行中。

## 问题与目标

[当前报告契约](../crash_reports_design.md)已提供私有保存，但用户还不能管理跨启动报告。
`CrashReportStore.read/ids/entries` 会读取 raw 或过滤未知格式，不能直接承担安全摘要和全部占用项的管理。
目标是在关闭普通日志时仍能发现报告，查看有限摘要、删除并主动导出；不改变采集、恢复和去重权威，
不扩展 T04/T05 全面治理、符号服务、遥测或自动上传。

## 方案与理由

### 用户入口与摘要

Android 的“工具 → 其它”增加“本地故障报告”，不依赖 `openLogs`。沿用 `ListItem.open`、
`CommonScaffold`、现有 Glyph/shape 与四语本地化；列表提供刷新、全部删除，详情提供摘要导出、
原始导出和单份删除。删除均确认；原始导出单独提示可能包含凭据、地址或内存片段，再明确选择继续。
普通查看不提供原文预览或复制。列表显示时间、来源、构建和可用状态，以及实际占用和
20 份／16 MiB／30 天限制；说明自动清理为尽力维护，未知格式也占额度。

新增 metadata-only inventory/summary 路径，只 stat 文件、读取最多 16 KiB metadata，不调用现有 raw 读取链。
白名单摘要重新构造，大小最多 8 KiB：来源/格式等封闭枚举、有效时间和数值、已知进程角色/ABI、
规范化版本号、限定库名及 APK SHA／GNU／Go Build ID。APK SHA 和 GNU 保留原十六进制规则；
Go ID 保留大小写与分隔斜线，仅接受 2 或 4 段、每段 20 个 `[A-Za-z0-9_-]` 字符，长度为 41／83。
此格式来自当前 Go 工具链的 HashToString 及包／二进制 build ID 组成，不接受任意文本或路径；
未知库、非法和过长值继续排除。详情与 JSON／ZIP 摘要使用同一白名单结果。
任意 identity/event 字符串、异常文本、路径、
processEpoch 和未知字段均不透传；非法或缺失字段显示未知，不用当前进程身份补齐历史报告。
元信息成功不表示 trace 完整：metadata-only、截断、原文缺失、未知 schema、metadata 损坏分别显示；
普通查看只核对原文存在/长度，校验和未核验须明确，不将它冒充原文完整性验证。
未知／损坏项可删除，摘要仅含管理状态及占用，原始导出禁用；metadata-only 不承诺自动补齐。

### 所有权、删除与迟到结果

`Tools → ReportView/provider → AppPlugin → CrashReports → Store/Worker` 是唯一调用链。
新增 IPC 仅接受 inventory、summary、delete-one/delete-snapshot、export、cancel-export，
参数是原生签发的条目 token、快照版本及封闭导出类型，不接受路径、文件名或目的 URI。
Store 持有至多 128 项、5 分钟有效的临时 inventory token 映射；它只关联已有目录项，既不复制正文也不持久保存第二份报告。
映射包含 no-follow 文件身份及 metadata 摘要；执行时重新核对，过期、替换或已删除返回 stale。
新 inventory 淘汰旧映射，调用方刷新后重新选择；超出目录遍历边界显示受限，不能显示空列表或清空成功。

所有文件操作仍经现有单 Worker／4 等待位串行执行，复用 1.5 秒任务期限与普通 Dart 2 秒等待；
每次执行重验 root 和子项边界，读取不创建/维护目录。管理路径不借维护函数间接读取 raw。
未知名称、非目录和损坏项也由原生枚举后签发 token；不把 basename 作为通用删除参数。
删除不解析正文、不跟随 symlink；边界外链接只处理链接本身，有限遍历/期限内不能完成时返回剩余项和失败。
全部删除只消费确认时的快照：逐项核对身份后删除，期间新收集项保留；部分失败不可写成全部删除。
删除正文保留内部最多 64 个已保存系统 ID，避免系统缓存立即回灌；不删除用户已导出的副本，
不重置 BootGuard 或禁止未来新故障。详情注明同一系统记录及当前进程重复指纹仍按既有规则去重。

provider 以页面/选择 generation 接收结果，删除后失效旧请求并刷新；旧列表或详情回复不能重新插入项目。
并发删除、采集、TTL 和导出由 Worker 操作顺序决定；已消失或身份变化的条目不改选为其它报告。
超时只停止等待，不虚称磁盘操作已撤销；原生仍占槽至实际退出，后续刷新核对真实结果。

### 导出与系统文件提供方

摘要为上述白名单 JSON；原始导出为 ZIP（同一摘要及原 raw.bin），必须先完整验证源长度和 SHA。
原始内容最多沿用 1 MiB，单份导出载荷硬上限 2 MiB；不输出整个 metadata.json。
编码／读回存在多份有界副本，2 MiB 不代表总堆上限；M1 已接受该口径，不新增堆峰值测量门。
普通查看、摘要导出不读取 raw。显式原始导出也只使用有界内存，不落共享 cache、临时文件或 FileProvider。

沿用 Android 系统 `ACTION_CREATE_DOCUMENT` 交互，由报告专用 AppPlugin 适配器持有 URI。
不直接用当前 `android_file_picker 1.0.1` 的保存实现：其 `writeBytesData`
对 null output stream 仍返回 URI，
且没有报告归属/撤销关联，无法满足本项失败与迟到要求；不顺带修改通用 picker。
适配器最多一个待导出会话，绑定 engine、请求 nonce、token、类型和一次确认；选择器等待不占 Worker，
最多 5 分钟。持久单调 request code 使用与现有扫码/VPN 不相交的范围，按扫码已有模式防止重启后迟到回调串单；
计数损坏/耗尽时拒绝导出，不复用旧 code。该标量放 noBackup，且不参与报告容量或正文删除。

选择器取消、页面退出、明确取消、engine/activity 脱离或会话到期即撤销；普通旋转也以取消收敛。
迟到回调不能启用新会话。系统返回后再次通过 Worker 核对源和权限，读取/编码/写入共用任务期限，
逐块检查撤销；删除先于取源则 stale，已开始输出后不承诺撤回已交给提供方的数据。
新 URI 只接受本次回调产生的 content URI，不持久保存 URI 权限，不交给 Dart 或普通日志。

open/write/flush/close 任一步失败均失败；支持读回时有界核对字节数和摘要，短写/不一致失败。
提供方不允许读回时仅显示“已写入，目标内容未核验”，不宣称完整保存。
取消/失败尽力删除本次新建文档；可能有部分副本留下或已同步，提示用户在目标检查。
阻塞的提供方 I/O 无法硬取消，继续占用原槽，不另开无界线程；固定错误码不带路径/异常原文。
系统目的地可能由云端提供方同步，选择前明确提醒；应用自身不调用邮件、WebDAV、上传或自动分享。

平台依据：[Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)
说明用户可选本机/云端提供方、创建新文档且目标副本独立存在；提供方行为不作纯本地或原子写入保证。
实现依据为当前 `lib/common/picker.dart`、`lib/views/tools.dart`、AppPlugin、CrashReportStore/Worker，
以及 `plugins/mobile_scanner/.../QrGallery.kt` 的请求归属模式。
