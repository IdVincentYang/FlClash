## 用户入口与结果含义

### 基础诊断

服务卡、列表单查和“全部检查”均只做基础诊断。一次 GET 只取 HTTPS 响应头，不读业务正文、不跟随跳转，不载入图片、脚本或页面其它资源。

| HTTP/请求结果 | 显示含义 |
| --- | --- |
| 2xx | 已收到 HTTPS 响应，显示 HTTP 状态码及响应头耗时 |
| 301/302/303/307/308 | 已响应并要求跳转；未访问跳转目标 |
| 401/403/429/451 | 已响应但受认证、访问或频率限制；不推断具体限制原因 |
| 其它有效 HTTP 状态 | 显示响应码及异常响应，不能宣称整个网络断开 |
| 连接/DNS/TLS 错误 | 本次请求未建立有效响应，使用固定原因类别 |
| 超时 | 本次请求超时；不据此证明服务、节点或全部设备离线 |
| 无有效结果/通道错误 | 检测未完成或无法判定 |

基础结果不包含 Premium、地区支持或播放权益。验证码可能返回 200 或 403；本用途只判断响应，不能将 200 等同于网页功能正常。
延迟是从本次 HTTP 发送到响应头的耗时，含连接/TLS，排除等待探测槽位的时间，不是 ping、吞吐或全设备延迟。

### 可选高级诊断

列表每项提供“地区/服务检测”入口（Google、GitHub 不提供）。进入详情只展示用途、接收方、操作说明和已有缓存；点击“开始检测”才请求。
高级检测不随服务卡 watch、基础单查、全部检查、切换节点、返回前台或缓存过期自动执行。它没有默认开启或持久自动开关。

详情同时显示独立的基础结果和高级结果；任一结果不会代替另一结果。高级入口说明：服务会看到此次出口；无浏览器登录态；检测不证明账号权益、实际播放或整个设备保护。
Disney 额外明确将执行匿名浏览器设备注册、令牌交换及会话查询；确认开始覆盖本次操作，不静默建立长期检测用途。

基础结果正常而高级结果地区不支持、被拒绝、规则不识别、超时，都保持基础结果原意；不提供“关闭 VPN/保护后重试”的建议。

## 接收方与最少数据

目标由随应用维护的静态表选择，Core 不接受调用方自定义诊断 URL、认证头或请求体。以下为拟使用目标，域名相同不代表任意子域均获允许。

| 服务 | 基础 URL | 高级用途及接收方 |
| --- | --- | --- |
| Google | `https://www.google.com/generate_204` | 无 |
| GitHub | `https://github.com/` | 无 |
| YouTube | `https://www.youtube.com/generate_204` | `www.youtube.com` 的 `/premium?hl=en`；地区/Premium 页面线索 |
| ChatGPT | `https://chat.openai.com/` | `ios.chat.openai.com`、`chat.openai.com`、`api.openai.com`；沿现有拒绝/地区检查端点 |
| Claude | `https://claude.ai/` | 同主机 `/cdn-cgi/trace`；服务报告地区 |
| Gemini | `https://gemini.google.com/` | 同主机页面的地区线索 |
| Netflix | `https://www.netflix.com/` | `api.fast.com` 与 `www.netflix.com`；诊断接口地区和指定目录线索，不执行测速下载 |
| Disney+ | `https://www.disneyplus.com/` | `disney.api.edge.bamgrid.com` 的 devices、token、device/graphql 三步 |
| Prime Video | `https://www.primevideo.com/` | 同主机页面的地区/限制线索 |
| Spotify | `https://www.spotify.com/` | 同主机既有 country-selector；地区线索 |
| TikTok | `https://www.tiktok.com/` | 同主机页面的地区/明确限制线索 |
| Bilibili | `https://www.bilibili.com/` | `api.bilibili.com` 既有指定番剧 playurl；仅该内容的地区响应 |

- 所有实际初始目标和跳转均须为 HTTPS、端口 443（显式 443 或省略）、无 userinfo；精确比较解析后的主机，不使用后缀通配。
  未知用途/服务直接拒绝，不回退其它服务或出口。
- 基础不跳转。高级 GET 只允许同一精确 origin 的跳转，每次最多 3 跳；跨源即停止并显示接收方限制/无法判定。ChatGPT 各端点仍分别请求；
  不为兼容跨源登录页扩大许可名单。
- Disney 所有 POST 禁止跳转，包括同源 301/302/303/307/308；逐步使用固定方法、固定路径和必要 Content-Type。
  断开步骤不能转发 assertion、refresh token 或 Authorization。
- 高级一轮最多 8 次实际 HTTP 发送（包括跳转），最多沿既有 5 个顺序端点；到限即无法判定，不继续尝试。基础每轮最多 1 次。保留总探测并发 8、
  服务并发 4、单次 10 秒及整轮 60 秒边界，不新增并发权威。
- 不继承订阅 URL/令牌、浏览器 Cookie、账户登录态或自定义设备标识。Cookie jar 为空，不复用 Set-Cookie。静态 UA
  仅表示合成客户端，不读取真实浏览器/设备参数。
- 保留现有 Disney 公共浏览器 client token、固定合成 browser/chrome/windows 参数；服务新发
  assertion/refresh token 仅存当前 Go 调用内，取消/完成即释放引用，不持久化、不返回 Dart、不记录原文。这里不承诺 Go
  堆内可验证清零。
- GraphQL/表单使用标准 JSON/URL 编码，不直接拼接服务返回字符串。解析要求状态码、必需字段、类型、长度及非空值匹配；
  不能用正则匹配到任意同名字段就成功。
- 返回 UI 的步骤说明只含静态端点标签、状态码、固定原因、耗时和路由链；不含原始正文、完整带查询 URL、Location、Cookie、认证或令牌。T07
  私有错误不打印底层异常原文。一般日志/订阅/WebDAV 的全面整改仍属暂缓的 T04/T05。

以上限制通过 serviceEnv 给 runProbe 的私有策略落实；其它 probe/outboundIp 消费者保持现有请求策略。
新增的正文读取结果在诊断规则消费，不能无意重定义其它接口的兼容行为。

## 高级判断与多步出口

### 结果必须有足够证据

高级结果包括“识别到地区/页面线索”“明确受限”“无法判定”；available 等既有内部状态在 UI 按用途解释，不直接显示为整个服务或账号已解锁。
结构化内容必须完整解析；完整正文失败、读取错误、达到体积上限但未取得充分标记、空正文、验证码/未知页面、未知字段或不符合预期的 HTTP 响应均不能落为成功。

扫描型页面可在取得完整且足够的目标标记时提前停止，明确记录“标记满足”，与 EOF、超限和读取失败区分。
保留当前小正文 16 KiB、HTML 512 KiB、扫描 8 MiB 上限；达到上限本身不能当作响应完成。基础不读正文。

| 规则 | 拟收敛的判断 |
| --- | --- |
| Claude/Gemini | 保留规范化地区；旧静态地区黑名单不作为当前服务可用性的证明 |
| YouTube | 明确 Premium 地区拒绝可显示；泛泛出现 Premium/ad-free 或普通 200 不足以判定支持/权益，地区线索与支持未知分别显示 |
| ChatGPT | 分别记录 iOS/Web/trace 观察；一个端点成功不掩盖其余失败，不以三者之一作全服务可用结论 |
| Netflix | fast 诊断只说明接口和地区；指定标题 200/404 只作目录线索，不单凭两个 404 证明仅自制剧或全部解锁；不访问返回 CDN 地址 |
| Bilibili | HTTP、JSON code 与必需播放信息同时验证；缺少 code 不能被 Go 零值当成功；只针对固定内容，不访问播放 URL |
| Disney | 三步均有效且最终结构化会话包含地区/支持字段才判断；任一步失败为未完成，响应 403 与明确地区字段分开 |
| Spotify/TikTok/Prime | 需要完整的目标字段/明确服务限制信号；泛 403、无标记的 200、服务页面改变不能猜为地区不支持或成功 |

### 延迟和路由不拼成一个误导数字

每个实际请求（包括已跟随跳转）记录自己的端点标签、响应头耗时、结果和实际路由链。高级详情展示这些步骤及总耗时；总耗时是整轮含排队/正文的墙钟持续时间，
不是网络延迟。
基础卡仅展示基础响应头延迟和其实际节点，不查询该节点 IP。ChatGPT 步骤另保留固定 `observation` 与规范化 `region`，与传输
`outcome` 独立；后续端点失败不抹去此前已识别的线索，单端点观察不能提升为全服务或账号可用。

高级不挑首步/末步来代表所有步骤，也不把不同链拼成一条代理链。所有成功步骤同一出口时可显示共同节点，否则显示“多个出口”并列步骤节点；缺失链显示“未知”，
不能猜成 DIRECT。
多步按既有规则独立选出口，不额外 pin 到某个节点，不因失败改直连。

复用现有 Core epoch/picks version：高级聚合记录整轮起点版本，逐步和结束核对；任一结构 epoch 或 picks version
变化即不发布为当前有效结论。
高级传给 RoutedProbe 的聚合 chains 留空，按现有无链规则保守要求 picks version 相同；步骤链仅供详情解释。
这样无需为多步增加第二套路由状态权威，代价是无关组的重选也可使本轮高级结果失效。
失效高级结果只显示已失效/需重新检测，不自动重新注册或交换令牌。

## 调度、资格、缓存与取消

服务启用仍由现有 disabledServices 决定；用途加入 ServiceStatus 的键和 Core 参数，基础、高级各自缓存与取消键，Core
claim 也按服务加用途区分。省略 purpose 兼容为基础；显式未知 purpose 拒绝。
names 为空为零项；应用 checkServices 也先短路空集合。所有正式消费者同步，旧“空为全开”测试预期不能保留。

RoutedProbe 继续拥有 watcher、due、inFlight、run 及缓存。只为本项增加可选的资格、自动用途及时间策略钩子，默认保持
OutboundIpProbe 原行为；不在 ServiceStatus 新建并行队列/路由订阅。
手动 due/inFlight 同样维持必要的 RouteTracker attach，使没有服务卡时手动检测也能取得既有路由快照；结束/取消后释放这一订阅。
attach 不代表取得网络运行权限。路由失效撤销 due/inFlight 后统一重算路由引用和 timer，不依赖旧请求的迟到回答收尾，
也不释放其它消费者的共享引用。
列表和高级详情另以 passive watch 持有正在展示项目的路由观察，不自动排队；沿 RoutedProbe 现有 watcher
记录区分自动与只观察的持有者，既有 watch 默认仍为自动。
因此手动检测完成后只要列表仍显示，结果不会因释放最后一个在途订阅而立即被清掉；关闭页面后可丢弃无消费者缓存，不为缓存常驻而维持后台路由监听。

| 场景 | 拟定语义 |
| --- | --- |
| 没有服务卡、没有主动检测 | 不请求服务诊断；本项不改变独立 IP 卡行为 |
| 服务卡稳定显示一个启用项 | 首次无有效缓存时自动基础检测；滑过其它项不请求 |
| 路由变化 | 旧结果立即失效；仅当前 watched 基础项可重新排队，高级不自动重跑 |
| 前台恢复 | 同路由且未过期的缓存直接显示；当前基础项过期/失败可重检；不追补后台次数 |
| 缓存年龄 | 结果保留在进程内，5 分钟后标过期；不伪装成当前值。路由变化比 TTL 优先，旧路由值不展示为当前出口 |
| 自动周期 | 当前被 watch 的基础项到期可检测；隐藏、无 watcher 或禁用时没有周期请求 |
| 限频 | 每服务每用途从上一轮实际启动起至少 30 秒，手动与自动均遵守；使用进程单调时钟，不受系统时间回拨影响 |
| 快速重复/全部检查 | 合并同键在途及一个待执行意图；不累积点击，不绕过限频；全部检查排队的是当前启用的基础集合 |
| 关闭服务 | 同时移除两用途 due/inFlight、取消 Request key、丢弃缓存并撤销结果资格；保留 UI watcher 数量但不允许请求 |
| 所有服务关闭 | 卡片/列表显示“全部关闭”及管理入口；全部检查禁用，不取 first、不 clamp 到负范围、不发 names=[] |
| 再次启用 | 只恢复当前被展示的基础用途；旧高级请求/forced 排队不复活 |
| 应用隐藏/关闭 | 取消本项在途和待执行手动工作，销毁唤醒 timer；后台不检测。恢复只按基础当前资格重新判断 |
| 单项/全部取消 | 删除 due，撤销 run 资格并 cancelKey；不能只停止加载动画；迟到回答不能写回 |
| Request/出口不可用 | 显示检测未完成，保留接受的路由约束；不自动改 DIRECT、节点或宿主保护设置 |

30 秒下限和 5 分钟 TTL 是本地经验策略，分别限制密集操作与长期展示旧观察；不是服务端额度承诺。最多维持一个最近到期 timer；
禁用/隐藏/dispose 必须重算或释放。
原 inFlight 记录在轮次 id 外保留明确手动标记；手动操作合并到在途自动检查时提升该原轮次，不创建第二份运行状态。
最后自动观察者离开即撤销未获手动意图的原轮次，即使仍有 passive 观察者；不能只取消 Request key。
已完成高级缓存的年龄在关闭/重开详情后仍保留。
基础手动工作可以在列表关闭后完成；有其它观察者时进入共享缓存，无观察者时允许释放结果，但仍受前台、启用、限频及取消约束。高级详情退出取消其在途/排队，
打开详情本身不发请求。
过期文案和年龄按观察完成时间显示，调度用单调经过时间；重启后无持久结果与待执行队列。

资格在入队、唤醒实际发起、Request await 后进入 Core 前及结果发布时再次读取；关闭不依赖 widget 及时 unwatch，forced
也不能绕过。
底层沿用 RequestSession scope/check/close、ServiceState 和 route tracker；不自建运行/暂停意图，
既有免责声明、Owner/版本和连接撤销继续生效。

## 实现落点与取舍

- 应用模型/桥接：purpose、固定原因/HTTP 响应、总耗时和受限步骤摘要；正常生成 Freezed/JSON/Riverpod，不手改生成文件。相同
  JSON envelope 与同包 Core 同步交付。
- ServiceStatus/RoutedProbe：用途键、资格/取消、可选计时策略和手动订阅持有；IP 消费者回归证明默认行为未变。
- 服务 UI：空状态、基础/高级区分、用途说明、实际节点与结果年龄、取消/限频反馈；移除 NodeAddressWatch 及服务展示中的 IP/质量消费。
  四种现有语言同步。
