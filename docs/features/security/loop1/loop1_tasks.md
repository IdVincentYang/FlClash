## 执行顺序与记录约定

- 两项删除任务交付后进入修改；修改任务完成并处理未决范围后进入增加。同组任务按下表依赖推进，不跨执行段提前加入产品能力。

- 任务为单层拆分；下表维护依赖与执行状态，本节记录协作归属，后文描述各任务的交付及验收出口。其它任务尚未实施，后续推进沿实际指派安排。
- 本阶段 D 以用户可直接沟通的独立 Codex 任务参与协作。M 为 Codex，负责目标与评审；
  L1-T01、L1-T02、L1-T03 的 D 为 D-02，协作入口为本地任务 `01a13492-b9fc-7db1-b654-9e7b98224587`。
  其它 D 待分派。任务设计先引用已有 plan/源码，独立设计文档确有需要时再就近创建并从该任务链接。
- IP 功能选择和扫码 SDK 处理未提前定案。可先核实事实并形成方案；依赖该选择的产品改动等决定明确后实施，其它不依赖的同组工作可继续。
- 若 IP 功能最终选择删除，执行前把对应任务调整到删除段并核对依赖，保持删除先行；保留时按当前修改方向推进。

- 目标与范围：核对移除 Crashlytics 后的 BootGuard/退出信息路径，保持故障循环恢复和失败次数处理，限制恢复对配置及现有诊断数据的清理。
- 设计入口：[本地恢复方向](loop1_plan.md#删除已拒绝采集保留可用的本地证据)、[BootGuard](../../../../lib/common/boot_guard.dart)、[启动处理](../../../../lib/bootstrap.dart)、[原生退出信息](../../../../android/common/src/main/java/com/follow/clash/common/GlobalState.kt)。
- 验收出口：正常启动、上次异常退出、连续启动失败和系统退出信息缺失均有确定行为；恢复不依赖第三方 SDK，不无提示删除配置文件/已有证据，不改变 ServiceState 的生命周期权威。
- 接续：此任务核对现有数据处理，尚未增加报告存储；新报告的保存/清理顺序由 L1-T11 接入时复验，避免依赖后面的新增任务才能交付本任务。

## L1-T11 增加本地崩溃证据保存

- 目标与范围：持久保存可获取的 Dart/Java 异常、Go/Rust/native 线索及系统 ANR/原生报告/dump，记录版本、进程、ABI、Build ID 和可取得的本地符号关联。
- 设计入口：[本地诊断需求](loop1_plan.md#删除已拒绝采集保留可用的本地证据)、L1-T10 的实际恢复路径、[构建指南](../../../development/android_build_guide.md)。
- 验收出口：受支持的异常/报告能跨启动保存、关联版本，恢复不会清掉报告；系统无报告、低 API、进程差异、磁盘失败和重复报告有明确结果。基础私有保存、资源上限、排除自动备份/上传随采集一起生效。
- 边界：说明每类报告的实际可获取条件，不保证完整进程内存或每次完整 dump；缺少匹配符号时记录限制。全量存储/备份审查与 Loop 3 对齐，正式符号保留及最终 APK 对应关系与 Loop 5 对齐。

## L1-T12 增加本地报告管理与选择导出

- 目标与范围：复用既有日志/文件入口，提供本地报告定位、摘要查看、删除和选择导出，落实容量、保留期限及原始报告与脱敏摘要的区别；沿用现有数据/导出边界。
- 设计入口：[本地报告需求](loop1_plan.md#删除已拒绝采集保留可用的本地证据)、L1-T11 的报告与覆盖说明。
- 验收出口：能找到跨启动报告及版本信息，清理/容量限制有确定行为；常规导出使用脱敏摘要，原始报告需明确选择；普通日志/配置备份不夹带原始 dump，也不自动上传或分享。
- 待细化：保存期限、容量及导出交互在任务设计时确定。保存到本地与主动发送给外部对象分别处理；既有 WebDAV 配置不自动授权上传崩溃报告。

## L1-T13 增加并核对正式联网用途清单

- 目标与范围：根据前面任务的最终实现，增加稳定的 Android 联网用途文档，记录触发、接收方类别/公开默认来源、必要数据、出口/失败策略、实现与验证入口，覆盖保留功能和 SDK/核心内部请求。
- 设计入口：[共同判定原则](../security_requirements.md#正常联网与额外暴露的判定)、L1-T01–L1-T12 的实际交付、[阶段完成方向](loop1_plan.md#完成方向与官方同步)。
- 验收出口：从实际入口能追溯到用途与接收范围，源码、依赖/最终包核对和受控观察互相对应；两项删除能力未回流，正常刷新/诊断/本地证据均符合要求；未知、失败、跳过和未验证分别记录。
- 交付：以 `docs/features/security/android_network_inventory.md` 作为稳定主题维护，不记录用户实际订阅、凭据或流量，不为每次编译新建报告。用途记录引用共同需求和 plan，不复制平行规则。
- 边界：本任务汇总 Loop 1 覆盖和剩余问题，不代替 Loop 7 的发布包整体验收，也不以短时无外发给出全局安全结论。

## 验证、跨轮接续与官方同步

- 每项任务在实施阶段选择覆盖自身行为的源码/静态检查、针对性回归、产物核对或受控观察，记录真实版本和条件。文中的验收出口是计划，实际结果与未执行项见各任务交付记录。
- 验证使用合成秘密、配置、二维码和报告，优先本地/受控目标；原始证据留在忽略目录或既有本地材料位置。必要公共检索不携带本地私有内容，对外发送按已有授权边界执行。
- 配置接受、业务路由/DNS 归 [Loop 2](../loop2/loop2_plan.md)，完整本机权限/数据生命周期归 [Loop 3](../loop3/loop3_plan.md)，可利用缺陷归 [Loop 4](../loop4/loop4_plan.md)，构建/符号/来源归 [Loop 5](../loop5/loop5_plan.md)，Geo 内容归 [Loop 6](../loop6/loop6_plan.md)。新增问题明确落点，不能因跨轮而漏掉应用联网路径。
- 每项交付按风险或行为保留窄提交、生成方式和验证入口，遵循[官方同步约定](../../../../CONTRIBUTING.md)。同步后复核已删除依赖、出口/认证、调度及报告行为；冲突处理理由写入对应任务设计/已有评审记录。
- Loop 1 完成时核对每项实际结果及未决选择，将真实版本、证据和限制交给 [Loop 7](../loop7/loop7_plan.md)；完成任务数量不能替代阶段能力与安全边界完成。
