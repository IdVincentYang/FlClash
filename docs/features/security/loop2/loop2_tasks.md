## L2-T01 最终配置与应用失败时的业务出口

- 目标与价值：正常配置及接受的 DIRECT/代理分流可用；新配置无效、缺失或应用失败时，业务流量不因默认回退而扩大直连，界面说明实际失败与仍生效的状态。
- 风险依据：本项修改前的 [applyConfig](../../../../core/common.go) 失败后仍应用内建默认配置并更新监听，[默认配置](../../../../core/Clash.Meta/config/config.go)为 Rule/空规则，普通[规则未命中](../../../../core/Clash.Meta/tunnel/tunnel.go)可选 DIRECT。源码风险需要真实消费者反例，不能仅凭静态路径宣称已发生设备泄漏。
- 范围：理清原始配置、脚本、用户覆写到最终配置及 Core 应用结果的优先级；核实首次启动、已有配置切换、解析/应用失败和后续恢复。以现有 configMu、配置对象、ServiceState 与业务监听所有权决定保留适用旧配置或停止受影响入口，不新增第二个运行状态权威。
- 正反验收：真实生产配置应用和本地业务流量经过正常代理及合法 DIRECT；坏配置/缺文件等失败后不会落到未接受的直连；已有适用配置、首次无可用配置、并发切换/迟到失败和成功恢复有明确结果。核对实际连接及服务/界面状态，不仅检查错误字符串、PROXY 标签或函数返回值。
- 设计入口：[L2-T01 最终配置与失败出口设计](l2_t01_plan.md)。
- 验证与交付：[L2-T01 验证记录](l2_t01_result.md)，包含真实消费者结果、源码/制品绑定、竞态失败及设备限制；M 已通过 I1–I8，源码提交 `4d442992150a492a6036a1ca9cafad749165fa7b` 已快进合入 `security/android`；任务临时分支已清理，共享目录、独立聊天和本地证据保留，待 M 对账并普通推送。
- 边界：首项不重做 DNS 全链路、订阅来源授权界面或脚本沙箱，不恢复暂停的 L1-T04，不承诺全设备 kill switch。必要核心增量、控制器兼容限制和累积源码载体要求见[设计](l2_t01_plan.md#范围与交付终点)。

## L2-T02 DNS 接收方、出口与失败回退

- 目标与价值：确认业务查询、节点启动解析、系统/TUN 与加密 DNS 的实际接收方和出口符合接受的配置，正常本地解析和必要启动解析保持可用。
- 风险与方向：最终配置会合并订阅、默认 DNS、用户覆写及可选系统 DNS；不核实可能把查询送到未接受的解析方或备用路径。沿真实解析入口检查 IPv4/IPv6、UDP/TCP、加密解析及失败回退，按用途决定限制，不预先替换用户所选 DNS。
- 验收出口：使用可区分接收方的合成查询证明正常与失败路径；拒绝和合法 DIRECT 分别有结果，不能以配置出现 DoH 或界面显示某解析器替代实际观察。
- 入口：[DNS 合成](../../../../lib/common/task.dart)、[配置模型](../../../../lib/models/clash_config.dart)、[核心 DNS](../../../../core/Clash.Meta/dns)、[Android TUN](../../../../android/service/src/main/java/com/follow/clash/service/VpnService.kt)。

## L2-T03 服务状态过渡与业务接管范围

- 目标与价值：启停、重启、权限撤销、服务丢失、网络变化及排除应用/网络时，实际业务流量处理和界面声明一致。
- 风险与方向：错误的运行提示或旧服务回调可能掩盖未接管/错误出口；沿 ServiceState 和已有核心/监听所有权处理，不建立新的 UI 状态仲裁者，保留用户接受的排除和正常直连。
- 验收出口：受控业务连接与可观察状态覆盖相关转换及旧回调；明确本地替身、设备/系统回调的证据层次，不承诺系统回调尚未送达时瞬时阻断全部设备流量。
- 入口：[ServiceState](../../../../android/app/src/main/kotlin/com/follow/clash/ServiceState.kt)、[服务实现](../../../../android/service/src/main/java/com/follow/clash/service)、[Android manager](../../../../lib/manager/android_manager.dart)。

## L2-T04 业务数据处理与额外传输审查

- 目标与价值：沿 TUN/本机代理到出站的生产路径核实业务数据仅用于接受的协议、路由、统计和诊断用途。
- 风险与方向：即使出口正确，内容仍可能被插件、镜像、日志或额外接收方复制。按实际调用与数据边界审查核心、已启用插件和统计入口；发现问题后再给出必要修改，不把名称匹配或没有观察到请求当作全局安全证明。
- 验收出口：给出已覆盖路径、实际接收方及必要数据的可追溯证据，处置已证实的额外传输；未走读的组件和无法证明的边界单列。日志字符串脱敏归 L1-T05，依赖来源与漏洞处理分别接 Loop 5/Loop 4。
- 入口：[核心业务路由](../../../../core/Clash.Meta/tunnel/tunnel.go)、[出站实现](../../../../core/Clash.Meta/adapter/outbound)、[流量统计](../../../../core/Clash.Meta/tunnel/statistic)。

## L2-T05 来源信任与配置内容接受

- 目标与价值：常规节点和规则更新在用户接受的来源委托范围内自动执行，高影响变化能被理解和接受/拒绝，拒绝时保留可用配置。
- 风险与方向：订阅、provider、脚本与覆写可能改变节点、规则、DNS、资源来源或安全策略；不处理会扩大来源被攻陷后的影响。使用 L2-T01 的最终配置边界比较实际变化，明确原始输入与最终生效内容，避免每次普通更新都弹确认。
- 验收出口：合成配置覆盖接受范围内的更新与超出范围的变化；拒绝保护已有配置，允许的分流保持可用。配置内容接受可先用本地输入验证，联网下载的身份、认证和跳转保护仍受暂停的 L1-T04 限制，不能据内容检查宣称来源认证安全。
- 入口：[配置合成](../../../../lib/common/task.dart)、[应用配置动作](../../../../lib/providers/actions/setup.dart)、[脚本执行](../../../../plugins/rust_api/rust/src/script/mod.rs)、[provider 解析](../../../../core/Clash.Meta/adapter/provider/parser.go)。
