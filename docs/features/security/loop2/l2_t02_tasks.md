## L2-T02-01 静态策略编译与本地消费闭环

- 目标：把封闭静态策略变成可单独使用的完整 YAML，实际核对业务与 DNS 的同序命中、显式默认和拒绝行为。
- 交付：应用侧严格模型、编译器及本地命令入口；用当前 Core 的真实配置应用、代理及 DNS 消费者验证生成结果。
- 范围：精确域名／后缀、IPv4／IPv6 CIDR、显式 DIRECT／代理组／REJECT，固定 SOCKS5 节点与有限 DNS 服务；具体白名单及失败
  规则以[首项设计](l2_t02_01_plan.md)为准。
- 验收：正常分流、重叠顺序、默认、无节点的合法拒绝、非法引用／不支持输入，以及 UDP 不能跨分支直连。源策略是唯一人工维护内容，测试不手写另一份待测路由
  YAML。
- 未接入：Profile 页面、DB、订阅迁移、常规 setup／T01 调度及运行中控制入口。该项完成只表示本地编译出口可用，不能显示或宣称应用已全面受管。
- 设计：[L2-T02-01](l2_t02_01_plan.md)。实际消费者、计数、运行前提与未接入范围见
  [验证记录](l2_t02_01_result.md)；自验通过不等于 M1 实现评审或本地交付通过。

## L2-T02-02 Profile 策略编辑、持久化与迁移

- 目标：用户在 profile 内维护一份策略，编辑、排序、默认和 DNS 选择均有明确含义，草稿可保存／备份／恢复。
- 出口：真实 UI 与 DB／备份迁移消费者可读写该模型；未知版本、缺默认和不兼容旧条件有可定位问题，不恢复默认 DIRECT。
- 旧规则迁移须保留关键 IP REJECT 及混合条件的影响说明；不能等价转换时只产生待迁移草稿。原始 YAML／DNS／全局规则的编辑与生成预览关系须清楚，
  不能保存后被无声覆盖。
- 与 03 的边界：本项交付草稿、迁移与预览；来源撤销及实际运行资格随 03 一起接入，不提前显示“已受管生效”。
- 设计：[L2-T02-02](l2_t02_02_plan.md)，包含独立草稿表、真实页面、旧规则提取、明文备份确认及恢复矩阵；验证、限制及基线既有失败见
  [本项结果](l2_t02_02_result.md)；M1 已通过实现复审，当前进行本地交付。

## L2-T02-03 最终合成、受管应用与恢复

- 目标：从 profile 策略、脚本及允许材料捕获同次快照，在最终编码前统一生成受管字段，沿 ConfigInput／T01 应用并显示真实结果。
- 出口：真实 setup 消费策略；空条目不恢复订阅规则，旧 DNS／sub-rules 不残留；保存、切换、删除和恢复纳入既有来源失效，坏候选保留适用旧输入
  或关闭。
- 受管状态收敛 Rule 模式、入站覆盖、外部控制和热更新写入口；内部 L1-T03 维护请求继续可用。明确 DIRECT 作为应用策略操作，普通组切换只能选
  择固定代理成员。
- 验收包含应用失败、并发停止、冷恢复及草稿／实际差异；节点／协议能力仅使用已经有独立验证的范围，不用 UI 文案扩大保证。

## L2-T02-04 订阅、集合与资产更新

- 目标：保留订阅自动刷新，把更新作为材料候选，校验、冻结、重编译并统一应用，避免核心后台独立改变受管闭包。
- 出口：真实刷新、provider 与 Geo 加载入口有可追溯快照；正常节点更新不逐次弹确认，失败保护适用旧配置；不能安全材料化的输入明确不支持。
- 扩展域名 keyword／regex／GEOSITE、GEOIP／IP-ASN、正常节点协议及组类型时，同时补两端顺序、启动依赖、能力和更新反例；不为扩展放
  开未知字段或特殊 resolver。
- DNS 传输扩展沿[总体支持及风险边界](l2_t02_plan.md#53-必须一起生成的-dns-字段)复审；DoH 当前不受支持，不能仅因初始 IP
  固定或 TLS 合法就恢复接受。
- Geo 更新按可核对的停止／重载边界处理，不承诺原子热换；更广的来源信任仍归 L2-T05。

## L2-T02-05 整项验收与能力说明

- 目标：将前项已交付能力按[M1 验证矩阵](l2_t02_plan.md#11-未来验证与完成判据)串成用户可操作闭环，核对业务、DNS 与 L1-T03
  维护请求的真实接收方。
- 出口：独立收件覆盖正常、拒绝、回退、更新和恢复；结果绑定实际源码、配置与制品。文档和 UI 分清已实现、未支持、未运行及未解决风险。
- 旧查询、缓存、远端解析和物理网络等剩余风险沿[总体设计第 10 节](l2_t02_plan.md#10-残留风险与不再承诺的能力)保留。设备／系统接管仍与
  L2-T03 对齐，没有真实环境证据的项不能写为通过。
- 完整范围与必要验收由 M1 最终评审；需要改变安全目标、修改 mihomo 或增加设备／对外权限时再交 M1 判断，普通实现细节不成为人类逐步批准门。
