# Loop 2：配置导入、路由与 DNS 信任

本轮要让“使用订阅上网”与“流量只去用户接受的出口”同时成立，防止配置导入、自动更新或 VPN 状态变化悄悄改变保护范围。对应[审计基线](../android_security_baseline.md) A-04、A-13。当前是待 review 的阶段方向，确定后再拆任务。

## 需求与需要保留的能力

用户需要导入和自动更新订阅，使用规则分流、节点选择与健康检查，也需要稳定的域名解析。正常节点更新不应变成每次必须人工确认；明确选择的 DIRECT、局域网访问与应用排除也应有可理解的行为。

本轮目标是明确配置来源的信任、最终生效策略与 DNS 接收方，让正常更新继续工作，高影响安全变化能够被识别并按策略处理。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| 导入及更新配置 | 配置可影响节点、规则、DIRECT、DNS 和远程 provider；应用已覆盖部分字段，不能假定所有原始字段原样生效 | 来源被替换或订阅被攻陷时，流量可能转向新节点、直连或未接受的 DNS 服务 |
| 配置、覆写与脚本合成 | 原配置、用户覆写和脚本共同生成实际配置；需要核验安全字段的优先级 | 只检查原始 YAML 会漏掉合成后的高影响改变，界面与实际出口可能不一致 |
| DNS 启动解析及回退 | 默认存在第三方 DNS；系统解析、节点地址解析、DoH/DoT、IPv4/IPv6 的实际出口仍需验证 | 查询可能暴露给非预期服务或本地网络；加密 DNS 仍会向选中的解析服务披露查询 |
| VPN 与路由状态变化 | 分应用、排除网络、撤销权限、断网重连及核心失败影响路由；“已启动”不等于所有流量都受保护 | 浏览器等业务流量可能在过渡期走系统网络，而应用仍显示保护已开启 |

上述是可信输入和出口边界的风险，不等于已证实某份订阅恶意或当前全部 DNS 都发生泄漏。

## 解决思路与取舍

- 对来源建立明确的信任记录，在下载、合成和应用新配置之间比较安全相关变化。正常节点列表刷新保持自动；新增直连范围、DNS 接收方、降级 TLS、远程资源或监听暴露等变化采用可解释的接受/拒绝策略，拒绝时保留可用旧配置。
- 在现有配置合成边界统一应用安全约束，明确订阅、脚本、用户覆写和应用策略的优先级；以最终生效配置和真实路由作为判断对象，避免界面开关被其它层覆盖。限制有能力改变信任边界的远程脚本与 provider。
- 分别核实业务 DNS、代理节点启动解析及失败回退。选择可信解析方、合适的加密方式与出口；代理尚未建立时需要独立的启动解析方案，不能假装所有解析天然经过代理。IPv6/UDP 也必须有确定的保护或拒绝行为。
- 区分应用自身请求与被 VPN 接管的业务流量。严格保护模式遇到故障时停止受保护流量；用户明确允许的直连或应用排除保持可见。系统级“阻止不使用 VPN 的连接”需要用户设置及兼容性验证，不能由 Dart 状态替代。[Android VPN 边界](https://developer.android.com/develop/connectivity/vpn)
- 沿现有配置模型和 ServiceState 实现约束，优先在应用合成层维护差异；确需修改核心时保留窄补丁及安全字段回归，便于跟进上游新增配置项。

## 整改收益与代价

收益是订阅自动刷新仍可用，同时能知道高影响变化是否改变了流量去向。代价是严格模式可能拒绝旧的不安全配置、增加高影响变更确认，DNS 保护也可能改变延迟或部分局域网兼容性。

需要 review 的是安全变化接受规则、DNS 服务及启动解析策略、严格模式的保护范围和直连例外。简单禁用全部订阅或强制改写所有规则会损害使用能力；默认接受全部变化则不能达到本轮目标。

## 范围、依赖与完成方向

- 使用 [Loop 1](../loop1/loop1_plan.md) 的下载、凭据和请求出口边界；本轮负责下载后的配置信任、业务路由及 DNS。监听访问保护归 [Loop 3](../loop3/loop3_plan.md)，Geo 内容真实性归 [Loop 6](../loop6/loop6_plan.md)。
- 完成时应能识别最终配置的安全变化，并验证正常自动更新、拒绝恶意/不安全变化、DNS 出口、IPv4/IPv6、VPN 故障和明确直连例外。未验证模式不能宣称受保护。
- 通过受控目标观察实际连接与 DNS 查询，不以原始配置、代理字符串或 VPN 图标代替证据。验证范围与发布配置由 [Loop 7](../loop7/loop7_plan.md) 汇总。
- 实施和冲突处理遵循 [官方同步约定](../../../../CONTRIBUTING.md)。
