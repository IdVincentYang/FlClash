# Loop 6：Geo 数据身份、内容影响与可信更新

本轮确认 GEOIP、GEOSITE、ASN 及相关 MMDB 是否对应接受的发布，解释历史差异，并保护正常更新及路由使用。依据[共同安全目标](../security_requirements.md)，对应[审计基线](../android_security_baseline.md) A-07。当前维护阶段方向，review 确定后再拆 tasks。

## 需求与正向价值

按域名、IP、地区和 ASN 分流需要数据支持，也需要跟随网络变化更新。目标是让每份启用文件有明确发布者、版本、来源和比对结论，并说明它怎样影响接受的规则。

真实发布、传输完整性、分类准确和最终路由分别判断。用户接受的 DIRECT 规则可以保留，数据被错误修改而扩大直连或更换节点才需要按实际影响处理。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| 历史文件差异 | 当前文件与审查日 rolling latest 不同，旧发布对应未闭环 | 无法区分旧版本、生成/筛选差异与篡改，不能证明历史文件身份 |
| 下载与发布身份 | latest 可变化，缺独立接受的版本/摘要或发布者签名约束 | 错误资产、渠道替换或发布者被攻陷的内容可能被当作正常更新 |
| 分类影响规则 | 数据是节点/DIRECT 等匹配的输入，实际影响取决于配置 | 特定域名/IP 被分到非预期出口；官方分类错误也能导致错误判断 |
| 替换与重载 | 现有核心有格式、内容变化及并发处理，发布校验未闭环 | 格式正确的错误文件被接受，或失败更新破坏可用数据/运行状态 |

数据文件不因参与路由就成为可执行代码；解析器缺陷归 Loop 4。新旧摘要不同只说明内容不同，不能独立证明篡改。

## 解决思路

- 为内置、缓存和运行中使用文件记录发布者/生成来源、固定发布或提交、资产名/格式、摘要及下载渠道。优先找同一发布者、同一版本、同一资产比较；若有本地加工，绑定工具与输入并解释差异。
- 对旧文件保留明确结论：与可信发布一致、已知加工差异、确认异常或历史无法证明。无法溯源时处置现用文件并建立新可信基线，不能用新文件可信推导历史未篡改。
- 核验传输与发布身份，优先使用可验证签名或独立接受的版本/摘要。区分阻止传输替换与防范发布者自身被攻陷；同一未经信任来源同时提供文件和摘要不构成独立证明。
- 比对必要的内容统计和代表性规则，检查异常分类变化，说明数据准确性的证据与限制。重大变化处理依据来源信任与影响决定，常规可信更新继续可用。
- 覆盖内置加载、首次补齐、手动/定时更新和核心内部路径。先验证再替换，失败保留已知可用版本；磁盘错误、并发、取消及热加载结果与实际文件版本一致。
- 自定义来源保留用途和明确的接受策略，说明校验证据与可见范围；不以永久停更或强制删除 Geo 能力代替处置。

## 收益与代价

收益是能回答文件是否与接受的发布一致，降低被替换数据影响路由的机会，也防止失败更新破坏分流。代价是旧文件溯源、可信版本维护与数据变更复核，替换数据集可能改变已有规则结果。

细化时确定受信发布者、旧来源未知文件的替换方法及自动更新校验方案。证据强度如实说明；发布签名能证明发布身份，但准确性和发布者自身可信仍有边界。

## 范围、依赖与完成方向

- 历史来源比对可先做；联网下载与认证/出口使用 [Loop 1](../loop1/loop1_plan.md)成果，配置接受和最终规则归 [Loop 2](../loop2/loop2_plan.md)。
- 格式解析缺陷归 [Loop 4](../loop4/loop4_plan.md)，非 Geo 嵌入资产及 APK 对应关系归 [Loop 5](../loop5/loop5_plan.md)。
- 完成时每份启用数据有发布身份、同版本比对和处置结论，错误来源/摘要/格式被拒绝，正常更新及失败保留路径可用。
- 实际规则结果绑定实际使用的数据版本；历史未证明项与剩余准确性风险交给 [Loop 7](../loop7/loop7_plan.md)，不把未发现异常写成绝对无篡改。
- 按[官方同步约定](../../../../CONTRIBUTING.md)复用现有核心更新边界，保留必要窄补丁和生成/校验入口；同步后复核默认源、格式、加载及校验路径。
