# Loop 3：Android 本机访问与敏感数据保护

本轮保护代理/控制入口、外部调用及本地秘密，保留合法共享、快捷操作、备份恢复和 bug 证据。依据[共同安全目标](../security_requirements.md)，对应[审计基线](../android_security_baseline.md) A-10、A-11、A-12。当前维护阶段方向，review 确定后再拆 tasks。

## 需求与正向价值

用户需要启停 VPN、使用系统快捷入口、扫码/链接导入、必要的本机代理共享，并能迁移配置、恢复备份和修复故障。能力应按用途授予，敏感数据的存储、备份和导出有可理解的范围。

目标是让其它应用和外部输入只能获得被允许的操作，正常私有保存和选择分享可用。loopback、私有目录或组件导出字段各自只说明部分边界。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| 本机监听与控制 | loopback 代理默认无认证，同设备应用可能访问；控制接口和局域网范围需一起核验 | 未允许应用使用代理/消耗流量，过宽控制入口可能读取配置或改变运行状态 |
| 外部 Intent/链接 | QuickActionActivity 与 MainActivity 有导出入口，具体校验和影响待核实 | 外部调用可能改变启停、导入非预期配置或获得超出用途的文件能力 |
| 凭据与系统备份 | 保存订阅、节点和 WebDAV 秘密，最终备份/迁移政策未闭环 | 秘密进入不适当的备份或导出范围，设备绑定密钥也可能导致迁移不可恢复 |
| 文件、恢复和诊断 | 已有提供方权限与恢复防护，仍需验证实际授权范围；dump 可含敏感片段 | 过宽授权泄露文件，恶意恢复输入覆盖数据，或 bug 报告被普通日志/备份带走 |

例如 FilesProvider 已有权限约束，需要核实有效授权及范围；仅看到 exported 不能认定它已经无保护。

## 解决思路

- 区分 VPN 接管、应用私用代理、允许的本机/局域网共享与控制 API。默认范围按用途收窄，必要共享采用可验证控制；涉及配置/控制的入口尤其核验认证、权限和默认 secret。
- 核验本机代理认证、应用自身客户端与 Android 系统代理的实际兼容性。保留用户接受的共享方式，具体限制依据风险和可行能力决定；不能承诺 loopback 自动提供逐应用身份隔离。
- 按动作与数据审查 Intent、Deep Link、扫码和文件入口，限制外部输入获得的能力。允许的系统快捷操作及用户主动导入继续工作，敏感配置应用有明确的接受边界。
- 分类处理秘密、普通设置、日志和原始报告，核实应用私有存储、密钥保护、权限及删除残留。按实际威胁选择加密和密钥方案，编码不视为加密，也不为普通设置无差别引入新存储体系。
- 明确系统云备份、设备迁移、WebDAV 和文件导出的范围。秘密备份采用匹配的保护/恢复方法，原始 dump 单独保管并排除自动备份；主动导出能选择内容，外部上传按授权执行。
- 保留并完善恢复的路径、格式、大小和资源限制；验证失败保护已有数据。删除、升级、重装和迁移的密钥/报告生命周期清楚，避免无提示丢失可用秘密或修复证据。

## 收益与代价

收益是降低其它应用滥用能力及凭据经文件、备份和诊断泄漏的机会。代价是代理认证、外部入口限制和加密备份可能影响部分客户端/自动化工具，并增加恢复步骤。

细化时需要确认真实共享/集成需求与数据保留策略。选择能约束风险又保持合法用途的方案；无法提供某种身份隔离时说明实际边界，不能把支持 VPN 的全部应用默认视为恶意或承诺无法实现的隔离。

## 范围、依赖与完成方向

- 本轮可先盘点本机入口与存储；本地报告的采集/脱敏和用途与 [Loop 1](../loop1/loop1_plan.md)对齐，本轮负责权限、存储、保留、备份和导出。
- 配置/业务路由归 [Loop 2](../loop2/loop2_plan.md)，实现中的可利用缺陷关联 [Loop 4](../loop4/loop4_plan.md)。
- 完成时真实未授权访问和恶意导入被限制，合法快捷操作、接受的代理共享及备份恢复正常；秘密/报告实际范围能被核对。
- 验证最终 manifest、文件授权、真实监听与恢复/导出结果；不能只检查目录名称或权限声明。未覆盖的系统版本及共享方式由 [Loop 7](../loop7/loop7_plan.md)说明。
- 按[官方同步约定](../../../../CONTRIBUTING.md)在现有 Android 权限和数据边界保留窄差异，同步后复核导出组件、权限、备份规则和新增入口。
