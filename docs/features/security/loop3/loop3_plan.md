# Loop 3：Android 本机边界与数据保护

本轮保护设备上的代理入口和敏感数据，避免其它应用、外部 Intent、备份或导出获得用户没有授予的能力。对应[审计基线](../android_security_baseline.md) A-10、A-11、A-12。当前是待 review 的阶段方向，确定后再拆任务。

## 需求与需要保留的能力

用户需要启动 VPN、使用快捷入口和配置链接，必要时让其它应用使用本机代理，还需要迁移订阅、备份配置和保存本地崩溃证据。

目标是让这些能力有明确的使用范围与数据边界：本机访问不自动等于受信任，导出不自动包含所有凭据，崩溃证据可用于修复 bug 而不会被顺带外传。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| 本机代理监听 | loopback 默认无认证；同设备具备联网能力的应用可能连接，局域网开放还受配置影响 | 未获允许的应用可能使用代理、消耗流量或探测出口；只绑定 loopback 不能提供应用身份隔离 |
| 外部 action 与 Deep Link | QuickActionActivity/MainActivity 有导出入口；具体校验及可利用影响需测试 | 若缺少必要限制，外部调用可能改变启停状态或引入用户未确认的配置 |
| 凭据存储与备份 | 应用保存订阅、节点和 WebDAV 凭据；最终 manifest 的备份/迁移策略尚未闭环 | 凭据可能随系统备份、文件导出或迁移离开原有保护范围；仅做编码不能作为加密证据 |
| 文件、日志与 dump | 已有文件提供方权限和备份输入防护，仍需核验真实范围；原始崩溃报告可能含敏感片段 | 过宽文件授权、诊断导出或恢复处理可能泄露数据、覆盖不该修改的文件或丢失 bug 证据 |

导出组件并不天然等于无保护。例如 FilesProvider 有权限限制，应核实其授权范围，而不是仅按 exported 字段认定已发生泄漏。

## 解决思路与取舍

- 明确 VPN 接管与本机代理监听的不同使用场景。默认收窄监听范围，为需要共享的代理设计认证或其它可验证访问控制；应用自己的请求同步适配认证，避免保留绕过前缀。
- 核验外部入口的调用来源、动作与参数，敏感启停、配置导入和文件操作按能力设限制。保留系统快捷入口和经用户允许的集成，不把所有 exported 入口一律关闭。
- 对数据分类：订阅/节点秘密、WebDAV 密码、普通设置、日志、原始 dump 分别决定存储、备份与导出。优先使用应用私有存储和合适的密钥保护，核实实际加密与访问权限，避免把可逆编码当成秘密保护。
- 明确系统云备份、设备迁移、WebDAV 和手动文件导出的范围。敏感备份需要可理解的加密与恢复方式；原始 dump 排除自动备份和常规导出，单独保存与选择分享。恢复继续校验路径、结构和资源限额，保留已有防护。
- 验证删除、重装与迁移时的行为：不能只删界面记录却留下可用秘密，也不能因设备绑定密钥丢失导致正常迁移无提示失败。安全策略尽量放在现有平台与数据边界，避免引入平行存储体系。

## 整改收益与代价

收益是限制其它应用使用代理或触发敏感操作，减少凭据与诊断数据经备份/分享泄漏。代价是认证可能影响不支持代理认证的应用，入口限制可能影响自动化工具，加密可能增加备份恢复步骤。

需要 review 的是代理共享需求、允许的外部集成、敏感备份范围和本地报告保留策略。认证方式也要考虑 Android 系统代理无法携带所需凭据的场景，不能以撤销保护或开放匿名访问作为静默兼容回退。

## 范围、依赖与完成方向

- 本轮负责本机访问、数据生命周期与备份保护；[Loop 1](../loop1/loop1_plan.md)负责外发/日志脱敏及本地报告采集，[Loop 2](../loop2/loop2_plan.md)负责配置和业务路由。保护策略需要相互对应。
- 完成方向是：未授权应用/Intent不能获得受保护能力，合法快捷入口和代理使用仍可工作；凭据、备份、恢复、清除与原始 dump 的实际数据范围可说明、可验证。
- 检查最终合并 manifest、文件权限及真实导出/恢复行为，不以私有目录名称、字符串编码或声明权限替代验证。受控测试包含恶意输入和允许的正常使用。
- 不承诺抵御已被攻陷的操作系统或具有设备最高权限的攻击者；必须明确客户端能保护的边界。实施遵循 [官方同步约定](../../../../CONTRIBUTING.md)。
