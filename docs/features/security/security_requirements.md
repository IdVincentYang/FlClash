# FlClash Android 安全目标与判定原则

本专题的安全目标是：保留正常上网及有用途的辅助功能，确保软件、依赖与构建产物可核验，行为符合用户接受的用途和配置，防止隐藏收集、额外上传、非预期流量改道和可利用缺陷造成的信息泄漏。

本文维护共同需求与判定原则。[总计划](flclash_security_plan.md)维护阶段入口、状态和依赖，各子计划维护阶段范围与解决方向；具体功能的保留/删除决定由 [Loop 1](loop1/loop1_plan.md#功能决定与待细化事项)维护。[审计基线](android_security_baseline.md)记录已发现线索，本文不把待核实线索改写成已发生的泄漏。

## 需要保护什么

| 对象 | 需要保护的内容 |
| --- | --- |
| 上网流量 | 访问内容、域名/DNS 查询、连接目标、流量记录和真实出口信息 |
| 配置与秘密 | 订阅 URL/令牌、节点密码/密钥、WebDAV 凭据、配置文件和备份 |
| 设备与诊断信息 | 稳定标识、与功能无关的设备信息、日志、崩溃报告及可能含敏感片段的 dump |
| 本机能力与构建环境 | 代理/控制入口、启停与导入权限、源码/依赖、构建凭据、签名密钥与最终 APK |

重点防范不可信输入、其它应用或外部调用滥用能力，以及配置源、下载渠道、第三方库、SDK、构建脚本和缓存引入的非预期行为。发布者或订阅服务被攻陷也属于需要考虑的风险条件。

## 正常联网与额外暴露的判定

每条联网路径按用途、接收方、必要数据、触发条件和实际出口判断。用户接受某项功能或服务后，可以在该用途范围内自动执行；订阅定时刷新无需每次重新询问。

| 场景 | 正常用途 | 应当处理的风险 |
| --- | --- | --- |
| 订阅刷新 | 向所选订阅服务提供必要认证，取得新配置 | 令牌进入日志、跨源跳转带走认证、SDK/第三方获得配置、未接受的出口回退 |
| 站点诊断 | 向所选 Google、YouTube 等站点发送必要的可达性/延时请求 | 携带无关凭据/标识、接触无关服务、在错误出口测试或误报保护范围 |
| 按规则上网 | 按接受的配置使用节点、DIRECT、局域网和分应用规则 | 隐藏改写规则、额外复制流量、暗中更换节点/出口 |
| DNS 与 IP 查询 | 所选服务收到完成解析或查询所需的数据 | 未接受的解析方、额外多方查询、降级传输或把显示遮罩当作外发控制 |
| 本地 bug 证据 | 在本机私有保存可获取报告，支持故障恢复与修复 | 自动上传/备份原始报告、常规导出夹带秘密、恢复过程清掉证据 |

网站、代理节点、DNS 与订阅服务的正常可见范围应说明清楚，数据量和接收范围应符合用途。用户会使用某个网站，也不代表已接受向它发送全部配置、凭据或长期后台记录。

## 共同要求

1. **行为透明且符合用途。** 保护应用自身请求与被接管的业务流量；删除已明确不要的统计和自动更新检查，逐项检查其它 SDK、核心内部下载与初始化路径。
2. **遵守接受的路由。** 正常 DIRECT、DNS、局域网和分应用配置可以工作。需要代理的路径不得静默改成直连；允许直连的路径也不得暗中转向其它代理或接收方。启动、失败和恢复时的实际行为与显示一致。
3. **秘密只交给需要它的对象。** 校验服务身份和传输安全，限制跨源跳转与无关请求携带认证，防止日志、备份、诊断和本机入口泄漏秘密。经过代理也需要检查 TLS 和接收方。
4. **源码与实际执行内容对应。** 补齐实际使用版本的项目和第三方源码，识别生成物、嵌入代码与动态加载，围绕敏感输入和数据传输进行安全审查。克隆完成只证明材料可取得，审查覆盖范围需如实记录。
5. **来源和行为分别核验。** Flutter 引擎、SDK/NDK、JDK、Gradle/Maven 工件等逐项确认发布者、版本、渠道和完整性，同时检查漏洞、权限、初始化及采集行为。官方来源不能单独作为行为安全的结论。
6. **数据身份可核对。** GEOIP、GEOSITE、ASN 与同一发布者、同一版本和同一资产比对；解释差异，验证更新。来源一致与分类准确分别判断。
7. **实质风险得到处置。** 按实际可达性和影响修复、升级、替换或限制危险能力。影响联网数据或凭据的重大未解决风险、关键未验证边界不能仅用提示文字算作完成。
8. **日常功能和故障可用性保留。** 自动刷新、常用站点诊断和本地 bug 证据要形成可用闭环；下载/配置/数据更新失败保护已有可用状态，避免用户只能关闭保护才能使用。
9. **审查持续对应安装包。** 结论绑定源码、依赖、数据、工具、签名与 APK；官方同步和升级后复核受影响路径，防止修复失效或被删除依赖重新进入产物。

## 范围与尚未选定的增强要求

本轮目标平台为 Android。匿名上网、所有应用请求一律经代理、故障时阻断全设备联网，以及全面重建所有官方工具/运行组件，属于可单独选择的增强要求，当前不作为默认整改条件。

敏感源码和生成代码优先建立可审查的来源关系；官方预编译组件逐项核验和审查后决定保留、替换或重建。具体的信任组件、构建范围与出处未知项由 [Loop 5](loop5/loop5_plan.md)形成清单，不预先以“有二进制”判定恶意。

客户端可以约束自己的代码、依赖、输入和被接管流量，无法证明第三方服务永远可信、保证互联网匿名，或抵御已控制操作系统的攻击者。选用某个服务仍存在相应信任，其可见范围和限制进入最终使用结论。

## 完成与使用结论

每项发现要说明实际对象、触发条件、可能影响、处理结果、证据和复核条件。区分已修复、已证实不影响、已缓解但有剩余风险、未解决和未验证；历史来源未知也要保留真实结论。

最终回答“此版本在什么配置和条件下是否适合上网、还有什么安全风险、问题在哪些组件”。结论需要正常功能、拒绝非预期行为和最终产物证据共同支持。编译成功、源码齐全、官方发布、扫描无命中或短时未观察到外发，都只覆盖部分问题。

## 官方同步与隐私约束

**持续方便同步官方仓库是共同工程要求。** 按 [CONTRIBUTING.md](../../../CONTRIBUTING.md)保留清晰的 fork 差异、窄补丁和验证入口；解决冲突时同时保留官方改进与安全需求，同步后复核受影响行为、依赖和数据身份。

审查与验证优先使用合成数据及本地/受控环境。原始配置、凭据、日志、抓包、dump、符号和 APK 留在本地；对外发送、上传或发布需有对应的用户授权。必要的官方资料查询与依赖下载按最少信息进行。
