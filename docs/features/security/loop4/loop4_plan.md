# Loop 4：Android 运行代码与可利用缺陷

本轮审查实际 Android 运行代码处理不可信输入的路径，核实并修复可利用缺陷。依据[共同安全目标](../security_requirements.md)，以[审计基线](../android_security_baseline.md) A-05、A-06 为起点，覆盖项目代码和实际运行依赖。当前维护阶段方向，review 确定后再拆 tasks。

## 需求与正向价值

代理核心、配置解析、脚本、原生桥接和 SDK 需要可靠处理网络对端、配置源、文件及其它应用提供的数据。修复应保留所需协议、扫码/编辑等能力和可用性能。

目标是把代码版本、Android 目标/feature、调用路径、输入能力和缺陷触发条件联系起来，处理能够影响秘密、流量、执行权限或可用性的风险。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| Go 网络协议代码 | Go/x/net 有 HTTP/2 公告匹配线索，Android 调用条件未验证 | 可达时可能由不可信网络对端触发公告描述的异常、资源耗尽或其它影响 |
| Rust 与原生依赖 | 锁定依赖存在公告线索，Android feature/链接结果会改变范围 | 可达缺陷继续存在，或把未构建依赖误判成实际漏洞而浪费整改能力 |
| Dart/Flutter、AAR/JNI 和 FFI | 实际运行组件、生命周期与数据所有权需结合最终包确定 | 只审 Go/Rust 会遗漏解析器、跨语言内存/状态错误及其它运行库问题 |
| 自有解析和输入边界 | 公开公告覆盖有限，配置/文件/脚本/桥接自身也处理外部输入 | 未公开的边界缺陷可能导致秘密读取、执行能力扩大、数据破坏或崩溃 |
| 修复兼容性 | 升级可能改变 API、ABI、协议、默认值及性能 | 正常节点失效、崩溃或策略变化，用户可能被迫回退到有风险版本 |

版本命中、代码存在、输入可达和成功触发分别记录。具体严重程度和影响由实际路径支持，不能从公告名称直接推导已经泄漏或远程执行。

## 解决思路

- 按实际 Android 目标、构建标签、feature 和加载结果建立代码范围，接收 [Loop 5](../loop5/loop5_plan.md)的源码/组件对应关系。官方组件也进入缺陷审查；未进入产物的依赖单独说明。
- 本轮开始时重新核实权威公告、受影响范围和修复版本，沿实际调用与外部输入判断可达性。扫描用于发现线索，关键网络/解析/桥接路径结合源码人工审查。
- 结合其它阶段的输入/权限边界，检查自有及三方代码的身份校验、资源限额、解析错误、文件/脚本能力、FFI 所有权及并发取消。不重复定义产品路由策略，发现具体缺陷返回所属改动边界处理。
- 优先采用兼容的上游修复，必要时维护可解释的窄补丁或输入限制；不需要的危险能力可明确关闭。需要保留的协议/功能应评估可安全实现的替代方案。
- 对每项风险给出条件、实际影响、处置和复核要求。可达重大缺陷及关键无法确认的输入边界必须处理，不能以关闭扫描或风险提示替代修复。
- 保留能发现关键缺陷重新出现的最小回归及符号/版本依据，检查安全升级后的功能和策略兼容性。

## 收益与代价

收益是降低恶意输入窃取秘密、改变执行/网络行为或使代理失效的机会，也减少只凭版本判断的误报。代价是源码审查和兼容适配，部分旧协议可能需要升级服务端或替代实现。

阶段范围围绕高风险可达路径持续扩充，明确实际审查覆盖和残余未知。源码齐全、官方来源和扫描无命中不能独立证明代码安全；不承诺发现所有未知漏洞。

## 范围、依赖与完成方向

- 基线 Go/Rust 路径可先审，完整范围接收 Loop 5 的实际清单；工具、库或 feature 变化时重新核实受影响判断。
- 运行缺陷由本轮归纳；联网用途归 [Loop 1](../loop1/loop1_plan.md)，配置/路由归 [Loop 2](../loop2/loop2_plan.md)，本机授权/数据政策归 [Loop 3](../loop3/loop3_plan.md)，来源和数据发布身份归 Loop 5/[Loop 6](../loop6/loop6_plan.md)。
- 完成时公告及源码审查发现均有实际条件、结论和处置依据；已修复路径经过针对性验证，所需正常功能保持可用。
- 重要未解决/未验证项不能当作安全通过，结果与 [Loop 7](../loop7/loop7_plan.md)最终 APK 输入对应。
- 按[官方同步约定](../../../../CONTRIBUTING.md)关联补丁与上游版本/公告，复用上游修复并撤销等价本地补丁，避免大范围三方源码重写。同步后重核 feature、输入能力与修复条件。
