# Loop 4：Go、Rust 与 Android 运行依赖漏洞

本轮确定公开安全公告是否影响实际 Android 应用，并修复能够触发的风险，避免把“依赖有公告”或“扫描未发现”直接当作安全结论。以[审计基线](../android_security_baseline.md) A-05、A-06 为起点，同时覆盖清单中其它实际进入 Android 产物的运行依赖。当前是待 review 的阶段方向，确定后再拆任务。

## 需求与需要保留的能力

核心需要稳定处理不可信网络数据、配置和协议，Rust 桥接/脚本能力也需要在 Android 上可靠运行。升级安全版本应保留所用代理协议、配置兼容性和性能，而不是为了消除扫描条目破坏使用能力。

目标是将实际版本、构建目标/feature、调用入口、外部输入和公告触发条件联系起来，给每项发现形成有依据的处理结论。

## 风险与不整改的后果

| 风险入口 | 当前事实与待核实边界 | 不处理时可能发生什么 |
| --- | --- | --- |
| Go 与网络协议库 | 构建使用的 Go/x/net 版本存在 HTTP/2 公告匹配线索；Android 可达性及条件未验证 | 若实际进入受影响路径，不可信服务端/数据可能触发公告描述的异常、资源耗尽或其它影响 |
| Rust 锁定依赖 | 存在公告匹配线索，目标与 feature 会改变是否进入 Android 产物 | 漏掉可达问题会保留风险；把未构建依赖一律算作可利用则会误导修复优先级 |
| 其它运行依赖与 FFI | Dart/Flutter、Android AAR/JNI 和跨语言边界也可能处理不可信输入；最终范围需与实际产物对应 | 只审 Go/Rust 会遗漏解析器、原生库或桥接中的已知问题 |
| 升级后兼容性 | 安全升级可能改变 API、ABI、协议或构建默认值 | 没有针对性验证会引入崩溃、协议失效或路由行为变化，也可能导致修复被回退 |

目前不能据版本匹配断言已经远程利用或泄漏个人信息。具体影响类型和严重程度应由公告、代码及输入可达性共同支持。

## 解决思路与取舍

- 按 Android 实际构建输入和加载结果确定范围，结合锁文件、构建标签、feature 与符号核实受影响代码。接收 [Loop 5](../loop5/loop5_plan.md) 的组件清单，补齐原生/SDK 依赖；不能仅从未按 Android 目标过滤的锁文件得出结论。
- 开始本轮时重新核实官方公告、修复版本与项目使用方式，区分版本命中、代码存在、输入可达和已能触发。自动扫描用于发现线索，关键联网/解析路径仍需人工核实。
- 对可达风险优先采用上游修复的兼容版本，升级工具链或库时同步核对调用和默认行为。无法及时升级时考虑窄补丁、限制输入或禁用受影响且不需要的能力，记录理由和复核条件。
- 对暂未修复项给出明确触发条件、实际影响、缓解方式和重新检查时机；可达的重大风险不能因已有缓解提示而自动视为完成。
- 将补丁关联具体公告和上游版本，保留能复现边界的最小回归；避免大范围 vendor 重写，方便上游修复到达后撤掉本地差异。

## 整改收益与代价

收益是降低不可信数据触发已知缺陷的机会，并减少误报造成的无效工作。代价是升级可能需要适配、影响性能或使旧节点协议失效；禁用能力可能让依赖它的配置无法使用。

需要 review 的是受影响功能确有使用需求时的兼容方案和尚无上游修复时的风险处置。来源可信、源码齐全或无扫描结果都不能替代漏洞与可达性判断。

## 范围、依赖与完成方向

- Go/Rust 基线审查可独立启动；实际运行依赖范围随 Loop 5 清单补齐。工具/库变化后，两轮都要更新受影响判断，最终由 [Loop 7](../loop7/loop7_plan.md)核对同一发布输入。
- 本轮负责运行漏洞及输入边界，依赖来源/预编译资产归 Loop 5，隐私采集归 [Loop 1](../loop1/loop1_plan.md)，数据发布者真实性归 [Loop 6](../loop6/loop6_plan.md)。
- 完成方向是每项公告具有版本、目标、触发条件、处理结论与证据，已修复路径通过针对性验证，正常代理/脚本功能没有因整改失效。
- 结论绑定受审版本；新增依赖、feature 或升级后需要复核，不能把“本轮未发现已知可达问题”写成永远无漏洞。提交与撤补丁遵循 [官方同步约定](../../../../CONTRIBUTING.md)。
