## 问题与方案

现有锁文件分别描述版本／依赖材料，既有记录只覆盖局部改动，不能回答每份实际装包对象来自何处、哪些工具仅在构建机执行。
采用一个长期来源说明加一个只读对账工具，复用现有锁、Gradle/R8／hooks记录和Geo核验；不新增权限DB、依赖管理器、自动下载器或另一份独立版本锁。

长期说明按对象解释用途、发布者／固定身份／获取渠道、摘要或签名依据、源码／生成关系、构建时执行／下载／装包／运行时加载或获取／未进入产物，以及known／unknown和后续任务。
版本权威仍为各正式配置／锁；APK逐项hash、source hash、ELF／Go metadata、R8映射、生成器及实际工具选择等机械明细由本次结构化证据承载，不复制成多人维护的长表。
按真实Android目标核Dart路径／git forks／本地插件、Go/Rust实际裁剪依赖、JVM release依赖与R8及native／资产；旧源码归档按精确对象选择性复用，不能由缓存存在推导装包。

拟增`tool/inspect_android_build_sources.py`，Python标准库读取显式APK及显式构建证据，输出派生JSON；不执行被检查文件、Gradle、hooks、生成器或网络，不默认扫描用户目录／全局缓存。
读取范围只来自调用者显式选择的文件／目录；证据中的路径不授权其它读取。相对路径、符号链接及archive entry不能突破该范围；外部SDK／缓存必须另外选择。
工具记录每个对象的原始／转换后hash、ABI／类型、来源候选、可证明的关系及unknown；区分原库→merge→strip→包，预编译件不冒称本地编译，AOT／DEX不能仅凭文件名认源码。
输入记录本身来自显式选择的证据，不从APK内附的manifest建立接受根；退出0仅表示结构及已声明字节绑定匹配，unknown必须保留，不输出笼统的trusted／secure结论。
报告从APK枚举出发，分列已对账、无记录、不可读取、unknown与矛盾；删记录、空集合及新增无记录条目不能变成完整覆盖。source hash、工具／Go元信息、R8映射只支持各自关系，不提升成构建因果。
不要求本项解决全部T02／T03问题；若当前上下文不足以绑定某个关键对象，明列所缺构建记录／源码或发布依据，不补造历史。
优先复用现存记录；若不足以恢复release依赖与实际工具输入，获实施授权后可按既有构建指南补一次必要的受控正常装配取记录。
新产物与历史包分别绑定，不用新构建反证旧包来源；只有旧记录确实不足时才使用这项实施验证许可，不为报告重复装配。
