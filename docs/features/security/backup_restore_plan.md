# Android 备份与离线恢复计划

状态：需求已记录，功能待开发。源码核对基线为 `security/android` 的 `581e305273b7`。

## 目标与范围

从旧 FlClash 迁移到全新安装的 MFC 时，用户应能恢复设置和已下载的订阅数据，逐订阅完成 **Review source**，期间无需重新下载。
现有 ZIP 已保存数据库、设置、主 YAML、脚本和本地 provider，缺少远程节点和规则 provider 的正文。
恢复后重新审核仍遵守现有来源授权契约。[现有归档逻辑](../../../lib/common/backup.dart) · [来源接受契约](source_acceptance_design.md#权威与接受对象)

- 继续保存现有用户数据，补齐所有已下载订阅的关联正文，包括未选中的订阅和 MRS 等二进制规则。保留来源声明、正文的对应关系及校验值。导出时缺少材料应列出受影响的订阅和缺项，不能标为可完整离线恢复。
- 第一版排除 GeoIP、GeoSite、MMDB 和 ASN 数据。全新安装使用目标应用离线写入的随包版本，无需增加 Geo 选项。
  源端更新过的 Geo 分类可能不同，自定义集合可能缺失，遇到缺项应提示。
  [随包 Geo 核验](geo_data_design.md#android-缺失-seed-核验)
- 继续使用逐订阅审核和目标安装的现有授权流程。归档范围为用户数据和已下载正文，排除旧授权、运行 checkpoint、连接状态与历史生成的最终配置。目标安装重新合成配置，动态脚本输出可以与源端不同。
- 继续兼容旧 ZIP。要离线迁移旧 ZIP 缺失的正文，需用支持新格式的源应用重新导出。也可由用户主动在线更新，获取当时服务器提供的版本。
  若需要覆盖安装旧 FlClash 来获取新导出功能，升级包须沿用旧应用的包名和签名，并使用更高的 `versionCode`。

## 实施方向

手动备份先建立归档与离线恢复流程。导出时核验数据库、主配置和 provider 映射在并发更新下仍能对应，优先复用 Core 现有的材料 lease 防止复制期间被回收。
导出结束后释放 lease，覆盖成功、失败和取消。恢复前在临时目录验证归档版本、路径、大小、校验值和映射，验证通过后按现有流程写入。
待审正文独立持久保存，重启后仍可审核。Review 仅使用匹配的本地材料，缺项应停止并提示。
恢复、Review 及其触发的配置应用均不隐式下载，后续主动更新仍走原流程。归档内容及其校验值不授予权限，恢复失败时的数据补偿也不恢复已撤销的权限。

自动备份复用同一归档流程。建议在应用运行时到期执行，启动或回前台时补做一次逾期备份。设置监听覆盖不了数据库和 Core 的材料更新，按修改触发需要额外接入这些入口。
同一时间只运行一次备份，成功保存完整的新归档后才轮换旧文件，失败保留最近成功备份并显示结果。
应用退出期间的备份等到下次启动补做。

保存位置、频率和保留份数待定。应用私有目录接入量最小，卸载或清除数据会一起删除。若需跨卸载保留，则考虑用户选定的外部目录。
备份可能包含订阅令牌和节点凭据。自动上传须由用户明确启用，手动 WebDAV 备份的授权仅用于该次操作。

## 验收

- 在全新 Android 安装中阻断联网，使用随包 Geo 恢复包含多个订阅及 MRS 规则的 ZIP，其中至少一个订阅未选中。
  重启后逐订阅审核并应用配置，核对正文一致，并检查日志中没有发起 provider 或 Geo 下载请求。
- 检查缺正文、损坏归档、源端自定义 Geo 集合缺失、导出并发更新及旧 ZIP。报告具体缺项，禁止审核时隐式下载或借导入恢复旧授权。回归现有合并、覆盖与失败补偿。
- 用可控时钟验证自动备份到期、回前台只补做一次、重复触发，以及写入失败时保留最近成功备份。复用[归档测试](../../../test/common/backup_task_test.dart)和[备份动作测试](../../../test/providers/backup_action_test.dart)作为回归入口。
