# 03 某 App 的目标列表只读页 Plan

任务入口：[NA-T01-03](network_activity_tasks.md#na-t01-03-某-app-的目标列表只读页)，规划基线 `801f533`。
本方案已获准实施：接通应用条目，按目标汇总该应用的活动；规则编辑和第三层目标详情仍由后续任务交付。

## 问题与目标

第一层已经展示应用活动，但无法继续定位该应用访问过哪些域名或 IP、分别命中什么规则及经过什么出口。
共享身份目前只有通用名称，用户也无法查看涉及哪些候选应用。
本项形成“应用网络 → 选择应用 → 查看其目标活动”的只读闭环，延续聚合视图，不改成连接日志流水。

## 方案与理由

### 入口与用户操作

- 从 Tools → Application network 点击应用条目进入，包括“显示全部应用”中的无活动应用。
- 标题保留应用名称与图标，提供包名识别信息。共享身份显示原记录的 UID 与候选应用名称／包名，
  明确无法区分具体发起者；未知身份仍保持独立，不借当前安装目录推定历史归属。
- 标题下常驻目标搜索框。默认显示该应用当前保留的全部目标，活跃目标优先，其余按最近活动排序；
  右上菜单提供“仅显示活跃目标”，不增加多组筛选 chips、常驻说明或手动刷新按钮。
- 每个目标显示域名或 IP、活跃数／保留连接数与最近活动的合并行、实际规则及出口概况。
  活跃数字沿用第一层的强调样式，零和无法确认的 `—` 使用次要样式；窄屏和大字体允许换行。
- 同一目标有多规则或多出口时，摘要明确标注数量，并可展开查看去重后的规则／出口组合，
  不把第一条当成唯一结果。此处只解释汇总，具体连接及来源追溯的排查界面由 04 提供。
- 返回第一层保留原搜索、显示范围和滚动位置。目标项不提供尚未实现的详情跳转、规则编辑或保存操作。

### 数据与状态

复用 `applicationActivityProvider` 和 `ApplicationActivityState.hostsForApp(appKey)`。
导航传递稳定身份键与必要的显示信息，列表持续读取当前汇总，不复制一份连接集合，也不新增轮询或订阅下载。
候选包名来自连接冻结的身份事实，当前目录只用于补充可读名称和图标；共享记录只计一次，不分摊给每个候选 App。

沿用现有 Host 归一化：大小写和尾点统一；没有域名时保留原目标 IP，两者都缺失时显示未知目标。
不合并不同子域名，不推测 IP 对应域名，不采集 HTTPS 路径或查询参数。搜索只过滤当前 App 的目标。
保留的规则／出口属于当时连接，不随当前订阅、分组选择或模式重新解释；一项包含不同结果时保持多值。

停止观察或快照失败后保留目标列表，活跃数显示待确认；只有完整成功快照才能确认归零。
仅活跃筛选依赖可确认的存活状态：暂时无法确认时保留内容并说明筛选暂不可用，不以空列表表示全部结束。
新 Native 实例沿现有规则清空旧内存，页面不显示上次实例的残留，也不自动跳到其它 App。
无数据时只说明尚无已观察活动，不据此断言应用未联网或未接管。真实读取失败提供原观察器的重试入口。

## 实施与验证

依赖 02；现有身份、App＋Host 查询和观察生命周期已经具备。本项顺序为：

1. 按本 Plan 细化页面布局与文案，接通应用条目和返回路径；保持只读边界。
2. 复用目标查询，完成搜索、排序、活跃筛选、规则／出口汇总与共享身份说明。
3. 覆盖自动更新、断开、失败、空态、应用目录缺失及返回状态；再构建并安装现有 AVD 验证。

关键验收：同一 App 对同一 Host 的多次连接只有一个目标项；另一个 App 访问同一 Host 不混入；
共享 UID 不选首个候选；域名未知时保留 IPv4／IPv6；多规则／出口可核对；旧事实不随配置变化改写。
页面测试覆盖入口、搜索清空、筛选、列表更新、返回和窄屏大字体；数据测试复用已有去重与生命周期用例，
仅为发现的缺口补充。设备验收核对真实应用与目标，修改运行状态或代操作界面遵守现有授权。
完成后提供可体验的 Android 测试包；Mock、本地渲染与设备实测分别报告，不互相替代。
