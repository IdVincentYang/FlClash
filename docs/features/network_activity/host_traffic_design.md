# Host 流量统计 Design

首版在 Android 从 Dashboard 找到本次 Core 运行中最耗流量的 Host，并查看 [应用网络](network_activity_overview.md) 保留的应用和连接记录。桌面暂不提供排行；不落盘，也不提供按天或按月的图表。

## 首版体验与口径

- 点击 Dashboard 的 **Traffic usage** 卡片进入 Host 排行，默认统计所有应用，包括身份未知但符合统计边界的连接。每项显示 Host、上传、下载和总量，按总量降序排列，同量按 Host 键稳定排序；支持按 Host 或 IP 搜索。
- 点击 Host 复用[逐连接详情](network_activity_design.md#目标的逐连接详情)，直接进入跨 App 范围，只展示同一 Core 运行仍保留的连接。现有明细观察依赖 Android VPN，仅代理模式和后台可能没有明细；即使明细为空，累计行也不消失。页面提示逐条计数之和不一定等于排行累计。
- 统计 Core 业务 Tracker 已计量的代理和直连字节，不包含绕过 Core 的流量或链路层开销。沿用应用网络对 `Inner` 的排除，也排除 Core 标记的路由探测；内部 DNS、底层代理拨号等非业务 Tracker 不计二次流量。排行不继承 Dashboard 的“仅统计代理”选项，因此不承诺与卡片总量对齐。
- 域名忽略大小写和末尾的根域点；同一目标 IP 上的不同域名分别计量。有域名按域名，无域名退回目标 IP，两者均缺失时显示“未知目标”。排行与连接详情使用同一键规则，不反查域名，不把无域名记录归并到同 IP 的域名下。
- 统计、搜索和详情跳转不主动请求目标 Host，不采集 HTTPS URL 路径或正文。排行入口保留连接的实际出口链，不挂载原详情页的出口检测图标；原应用网络入口不变。

## 数据源核查与方案取舍

| 当前源码 | 能提供的数据 | 不能承诺的能力 |
| --- | --- | --- |
| mihomo [Manager](../../../core/Clash.Meta/tunnel/statistic/manager.go) 和 Core [事件桥接](../../../core/hub.go) | Tracker 加入时发 request 事件，`getConnections` 读取仍在 Manager 中的 Tracker | 没有结束流量事件。两次快照之间结束的短连接，可能只收到加入时的计数，甚至没有记录 |
| [应用网络观察器](../../../lib/providers/application_activity.dart) 和[连接记录 Store](../../../lib/common/application_activity.dart) | Android VPN 可用且应用在前台时约每两秒拉取快照；页面不必打开；最多保留 4096 条明细 | 应用退后台会停主动轮询；实际送达的加入事件不提供最终值。保留明细不是完整历史，淘汰后不能靠列表重建累计 |
| mihomo [TCP／UDP Tracker](../../../core/Clash.Meta/tunnel/statistic/tracker.go) | 已在数据路径记录上传、下载字节；Tracker 可在 Flutter 不可见时继续计量，只要对应 Core 仍在处理转发 | 当前 `Close` 先从 Manager 移除 Tracker，再关闭底层连接；不能把新增一个普通关闭回调直接当成可靠的最终读数 |

**Core 累加，Flutter 只读取。** mihomo 在业务 Tracker 发布前绑定计量回调，覆盖 TCP／UDP 初始字节、普通读写、buffer 和 unwrap。Core 固定每条连接的 Host 键和纳入资格，首次产生正字节时绑定计数器，后续 I/O 用原子加法。`getHostTraffic` 返回 Core 实例标识及只读汇总；不叠加快照或 request 事件，也不向 Flutter 推送逐 I/O 事件。短连接及最后一笔已经过 Tracker 计量的字节不依赖关闭通知；只要 Core 仍在转发，统计就不依赖 Flutter 是否在前台。

未采用快照加加入事件方案：即使单独保留去重基线，也只能得到有观察缺口的流量，无法补齐后台或两次快照之间的短连接。

## 生命周期与容量

- 只在内存保留本次 Core 运行的累计。Core 实例更换从零开始，旧实例迟到的快照不混入新实例；页面刷新、前后台切换、连接记录淘汰和 Dashboard 现有计数重置均不改变 Host 周期。连接计数重置或 ID 复用不参与排行去重。
- 排行打开且在前台、转发可用时，Flutter 串行刷新汇总。停止转发后保留 Flutter 最后成功读取的排行并标明不是最终结算；若 Core 仍存活，恢复转发沿用同一周期。归属以 Core 实例标识为准，不以开关状态推断。
- 明细与排行汇总分离。最多保留 8192 个独立目标桶（含未知目标）；达到上限后，新目标归入不可下钻的“其他目标”，并在页面说明。已纳入目标不被替换，累计不会因新目标进入而下降。

## 验收

| 验收场景 | 预期结果 |
| --- | --- |
| 同一域名不同大小写、带尾点、多 App、多连接；同 IP 上有不同域名及无域名连接 | 同域名合计；不同域名与 IP 分开；每条业务连接只贡献一次 |
| 前台反复刷新、迟到响应、计数重置、Core 重启及连接 ID 复用 | 累计不重复、不串代；周期内计数不会因重置观测值而减少 |
| 短连接、连接结束前的最后字节、应用后台持续转发、Core 内部检测 | 按所批准的数据源口径覆盖；Core 计量方案须覆盖 TCP／UDP 短连接与后台计量，排除既有过滤规则认定的内部连接 |
| 超过 4096 条明细、Host 桶满额 | 旧 Host 累计不下降；下钻提示明细可能不完整；超出 Host 容量的字节有明确去向 |
| 排序、搜索、详情、停止／恢复／重启 | 全应用排行正常；下钻直接显示相同 Host 的保留连接；周期与停止态显示一致；操作不触发目标请求 |

设备上的生产 VPN、Core 和 JNI 验证复用[本地回声夹具](../../../android/tests/device/network_activity/README.md)，不访问外部目标。该功能不修改转发生命周期或 Dashboard 现有总流量。
