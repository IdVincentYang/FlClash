# 03 某 App 的目标列表只读页 Result

NA-T01-03 已实现应用条目 → 该身份的目标列表：支持域名／IP 搜索、活跃优先排序、仅活跃筛选，
并可展开实际规则／出口组合。共享身份可查看 UID 和候选应用，未知身份不猜测归属。
具体连接详情、接管和规则编辑仍属于后续任务；有效契约见 [Design](network_activity_design.md)。

## 检查与实际结果

| 检查 | 结果 |
| --- | --- |
| 锁定依赖、intl_utils 生成 | 成功；锁文件不变，四种本地化经生成器产出 |
| 静态分析 | 无错误／警告／新增 info；42 条原有 info |
| 页面与预览 | 33 项通过，包含普通、共享身份、窄屏大字体及三种非英语布局 |
| 定向回归 | 116 项通过，覆盖导航／搜索、活动生命周期、本地化和相关 UI lint |
| 扩展回归 | 598 项通过、4 项失败，失败范围见下文 |
| APK 与安装 | 最终构建无重建提示；签名有效，覆盖安装后摘要与构建 APK 一致 |

页面验证同一 App 同一 Host 的聚合、另一 App 不混入、域名归一化、IPv4／IPv6／未知目标、
规则与出口的实际配对、共享候选、未知身份、停止保留、新实例清空及失败时活跃值待确认。
仅活跃筛选遇到未确认状态回退保留列表；搜索／展开状态随自动更新保留，返回恢复第一层搜索、范围和滚动位置。
测试发现并修正新增目标继承其它目标展开状态的问题，使用每个目标的 PageStorage 身份隔离，
对应重排与返回用例已通过。原始连接事实及不同查询范围的隔离继续由既有汇总测试覆盖。
本地渲染已检查共享候选、规则／出口组合和窄屏大字体；测试字体缺少链路箭头字形，不能据此判断系统字体显示。

扩展检查的 4 项失败与上一轮记录一致，相关生产路径和测试相对实施基线均未修改：
3 项 update_dialog_test 的人工 release 结果被 Request.validateVersionResult 拦截；
1 项 uncovered_views_test 的脚本编辑用例无法加载本机 macOS Rust 库，报 LINKEDIT string pool 未对齐。
未将扩展检查写成全套通过，也未在本项修改这些无关功能。

## Android 只读验收与交付边界

在现有 emulator-5554 上保留数据覆盖安装，未创建 AVD、清空应用数据或导出 Downloads 副本。
按用户授权只操作只读页面：Tools → Application network → 显示全部应用 → 搜索已安装 Chrome →
打开目标列表，核对名称／图标和包名，测试目标搜索、清空、空结果及返回恢复应用搜索。
结束后恢复原 Dashboard 和停止状态，删除模拟器中的临时 UI dump；未点击 Start／Stop、接受来源或修改规则。

安装后代理处于停止状态，因此本轮设备检查不证明实时目标、共享 UID 候选和多出口展开的实际设备流量结果；
这些数据展示状态由上述页面测试及预览覆盖。Native 采集和真实连接回放的既有边界仍沿
[01 Result](na_t01_01_result.md)及 [02 Result](na_t01_02_result.md)，本轮未重新执行其会替换配置的网络夹具。
本项交付第二层只读页面，不宣称第三层或就地分流闭环已完成。
