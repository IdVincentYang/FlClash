# 08 应用网络快捷入口 Plan

任务归属：Codex；输入基线 c9d39b8。07 的验收、提交及根仓库推送已完成，本项接续实施。
需求来自 [Overview](network_activity_overview.md)，状态由 [Tasks](network_activity_tasks.md)维护。

## 目标与界面

Dashboard 增加可添加、排序及移除的“应用网络”卡片，标题进入现有完整应用列表。
卡片展示最多三个应用，与完整列表相同：失效项前置，其余活跃项优先；应用 item 与 Application network 共用 UI 和行为：
应用图标、名称、连接数／时间、出口、策略标题／开关和 item 点击均由同一组件及相关逻辑维护。
点击 item 主体进入该 App 的 Host 列表，右侧策略控件仍执行当前应用策略操作。
条目及候选列表由共用组件／展示逻辑提供；列表专属搜索与滚动时顺序保持在完整列表维护。
名称截断、共享／未知身份、失效与暂停状态、操作忙碌及失败反馈两处保持一致。
卡片按同一条目高度容纳内容，不为压缩卡片另建简化交互。默认布局和旧用户卡片配置保留，
由 Dashboard 编辑模式添加卡片；空态提供进入完整列表的入口。

Recent requests／Live connections 的共用连接详情增加应用和 Host 查看跳转，保留复制。
有可靠应用身份时进入相应 App 或 App＋Host；未知／共享身份保留原观察范围，不按旧 process 字段猜测。
无 Host 时使用已知目标 IP；无可用目标时不提供无效跳转。
从应用网络打开详情时保留返回上下文，避免向相同目标重复堆叠页面。

## 实现与依赖

提取现有应用 item、展示数据和操作入口为两处共用单元，复用 02 的活动汇总、应用目录及 05–07 策略状态。
只读入口和渲染不增加观察任务、下载、来源审核或隐式 Start；渲染也不增加出口检测范围。
Dashboard 恢复已保存卡片时先等待既有 initProvider，再读取候选和策略状态；
启动恢复未完成时只显示等待状态并禁用查看跳转，避免提前初始化 Native／Request 依赖。
通用连接详情的快捷入口由 Android 调用方开启；旧无版本化 observation 的记录保留原详情及复制。
Dashboard 与应用列表使用相同排序／身份语义，卡片只限制条数；页面专属搜索和“全部应用”筛选留在列表。
连接详情使用现有导航及三层页面，不新增规则编辑器、采集字段或持久历史。
