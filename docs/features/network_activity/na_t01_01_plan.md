# 01 应用身份与连接信息采集 Plan

对应 [NA-T01-01](network_activity_tasks.md#na-t01-01-应用身份与连接信息采集)，基线 048e99b。
用户已授权完成本任务及其验证，不推进 02–08，不新增正式页面。

## 问题与目标

现有 Android 连接身份依赖进程查找配置；UID 的包名解析取首个候选并在服务内长期缓存。
这不足以支撑可信的 App 汇总。连接已有规则、出口和可选来源追溯，但缺少明确的识别状态、
运行实例及实际接管关联。目标是沿现有事件与快照输出可靠事实，未知不猜测，旧事实不重算。

## 方案与理由

- 在 FlClash 的 Android TUN 接入层记录接管实例及进入时的运行上下文，沿原 Tunnel 转交流量，
  不改变服务意图、来源接受或 mihomo 路由所有权，也不增加子模块补丁。
- 连接加入现有统计器时补齐应用观测，不依赖 App 规则或进程查找开关；已有规则查找仍走原桥接。
  只解析真实 socket 的 UID。包名解析明确当前 Android 用户范围、候选唯一性及失败状态，
  去除长期 UID→首个包名缓存，防止卸载重装后沿用旧归属。
  Android 29 以下沿用 procfs，但相同本地 socket 对应多个 UID 或表不可读时返回未知，
  不采用首行结果；旧平台实际系统访问能力须单列验证边界。
- 通过现有 Android JNI 的包名回调传递结构化解析结果，Core 仅把唯一且可确定的包名用于原有进程规则。
  连接对外附带版本化 observation：应用身份、运行实例、接管证据、配置及路由版本。
  原有 metadata、规则和 chains 保持兼容；来源追溯继续由原 matcher 提供。
- 事件在连接加入时冻结 observation；快照只读取这份事实，不重新查询 UID、当前分组或当前配置。
  过渡中不能证明的版本、非 TUN 入口及未取得的身份明确未知。原始入口关联和冻结缓存均有上限，
  超限降为未知，不把后来采样伪装成原始事实。本项不实现活动汇总或事件持久化。

## 实施与验证

先补 Android 候选解析与测试，再接入 Core 入口观测／冻结数据和 Dart 类型，最后做跨层与设备验证。
实现完成后新增模块 Design 记录已实现契约，维护实际受影响的 architecture，并在本任务 Result 记录证据；
Tasks 仅维护状态与链接。

验证使用两种包名／UID 的受控客户端和本地 TCP／UDP 服务，由客户端 socket 事实及服务收包建立独立依据。
不含 App 规则的 Rule／Global／Direct 场景须取得正确归属；事件、快照及 Dart 解码须对同一连接一致。
通过可区分的直连和受控代理核对规则与出口；配置切换后旧连接事实不变。
共享 UID、不同用户、查找失败、UID 映射变化、服务更换和容量边界由针对性测试覆盖；
设备未实测的条件单列，不把替代测试写成系统级验证。正常场景不能以全部未知通过。

性能以同一受控连接负载下的基线／新版本比较，记录识别耗时、连接耗时、吞吐及内存边界；
判定至少要求无归属错误、无新增连接失败、无逐包重复识别及无随累计连接数持续增长的缓存。
实际 Android UI／VPN 操作遵守用户的 Computer Use 许可，构建复用既有缓存，避免复制 Gradle home。
