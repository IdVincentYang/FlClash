## NA-T01-01 应用身份与连接信息采集

本项是基础实现任务，交付修正后的采集链路和供 02 消费的连接数据，不以调查报告或字段说明作为完成出口。
复用现有应用目录、Android／Core 识别桥接、请求事件和当前连接快照，具体实现范围为：

- 接通应用识别的有效触发：即使没有配置 App 分流规则，受接管的连接也能尝试识别所属应用；所需配置沿既有接受流程采用。
- 修正 UID 到 package 的归属处理：明确用户范围，处理候选不唯一、识别失败及缓存失效，不把共享 UID 的首个包直接当成确定身份。
- 补齐并统一事件与快照中的连接信息：连接 ID、Host／IP、应用身份及识别状态、实际规则与出口、当时的配置版本和接管状态。
  复用已有字段与来源追溯，只有真实取得的信息才标为已知，不用当前配置回填旧连接的缺失事实。
- 将这套数据通过现有 Core → Android 通道 → Dart 路径交给后续消费者，保持原 Requests 和连接详情可用；
  已完整具备的部分直接复用，按实际缺口补代码，不再搭一套独立采集系统。

验收以运行结果为准：未配置任何 App 规则时，两个受控 App 的 TCP／UDP 连接仍能正确归属，
事件与快照对同一连接的身份一致；共享 UID、重装／UID 变化、未知或不支持场景不误归属。
配置切换不改写已取得的旧连接事实；识别开销有实测结果。交付代码、对应测试和实际支持边界。

本任务不新增正式页面；现有连接详情可辅助核对，完整“应用网络”入口在 03 交付。
运行期汇总归 02，App 分流设置归 05–06，策略优先级等业务取舍在 05 编码前确定。

## NA-T01-02 运行期内存汇总

基于 01 的事实建立 App、App＋Host、Host 跨 App 的有界内存汇总，提供三层页面共用的查询结果。
连接加入事件补足短连接，成功的完整连接快照校对活跃状态；去重并隔离旧运行实例的迟到事件。
观察生命周期独立于页面，规定容量、清空与重启边界，保留记录发生时的规则及出口。

验收：同一事件不重复计数，短连接不因页面轮询间隔遗漏；快照读取失败不把所有连接判为结束。
离开页面或进入后台后按已声明覆盖继续观察，进程结束允许重置；数据缺口明确标示。
清空统计不删除规则，超过上限仍保持有界，不落盘连接事件。

## NA-T01-03 三层只读页面与基本入口

提供 Tools 的独立入口，以及应用活动、某 App 的 Host 列表、Host 详情三层页面。
接入“全部应用”，展示接管状态、默认策略占位或既有设置、实际规则与出口、近期汇总及观察范围。
第三层保留 App 上下文，并能显式切到同一 Host 的所有 App 视图。

验收：用户能从 App 定位到有问题的 Host 并理解实际路径；多规则、多出口、未知、未接管、
无权限、尚无数据与零连接各有正确含义。只读阶段不提供假保存操作，也不把未实现策略显示为可用。

## NA-T01-04 应用接管控制闭环

在应用页面就地修改是否接管，复用现有全局 Access control 的全部／仅选中／排除选中语义。
新旧入口共享设置，保留已有列表；将保存、VPN 重建及实际采用的状态反馈接入页面。
未接管 App 的旧统计仍是过去观察，不能借此声称当前可观察。

验收：断开时可编辑且不自动 Start；运行中通过既有服务流程采用，说明可能的短暂中断。
快速修改、Stop、撤销与失败时不被迟到结果覆盖；系统限制下不把“未接管”保证为直连或断网。

## NA-T01-05 App 默认分流闭环

完成 App 默认策略的持久保存、规则组合与采用，并在应用页面支持跟随现有分流、直连、指定分组。
本任务 Plan 在编码前核定订阅归属、模式影响与规则优先级；模型须容纳已知的 App／Host 作用域，供 06 复用同一保存与采用链路。
关联当前 Profile 与可用分组，明确模式不适用、目标失效、已保存但未采用等状态。

验收：连接实际使用所选策略；App 默认选择跟随后恢复原有规则路径，重启保留设置。
未接管时预设策略不暗中开启接管；切订阅、删除目标、待审来源或应用失败不静默直连，旧观察不改写。

## NA-T01-06 Host 例外与跨 App 操作

从 App 的 Host 列表与详情设置“仅此 App＋此 Host”的例外，复用 05 的持久配置与采用机制。
补齐“本订阅所有 App＋此 Host”的显式操作，处理优先级、重复规则、已有手工规则冲突及移除例外后的回退。
默认按准确 Host／IP 建规则，不自动扩大成域名后缀；更宽匹配的交互细化时明确范围。

验收：App A 与 App B 访问同一 Host 可以分别使用两个分组；局部修改不影响另一 App。
验证例外、全局 Host 规则、App 默认与原有规则的实际顺序；跨 App 查看本身不修改规则。
修改后通过新连接确认结果，旧连接及过去汇总保留当时事实。

## NA-T01-07 Dashboard 与连接详情快捷入口

提供 Dashboard 应用活动卡片及现有连接详情的 App／Host 跳转，进入与 Tools 相同的三层页面。
复用 02 的汇总及统一策略状态，不因入口不同建立另一份缓存、规则编辑器或观察任务。

验收：卡片查看全部、点击某 App、从连接进入目标均保留正确订阅和作用域，返回路径合理。
可先交付只读入口；整体收尾前须接通 04–06 的操作和生效反馈。

## NA-T01-08 Android 完整验收与交付

整体验证“观察 → 定位 → 修改 → 验证”，覆盖接管、App 默认、Host 例外、跨 App 视图与全部入口。
覆盖后台、前台返回、断开重连、配置切换、重启清空内存、规则保留及分组目标失效。
按改动补齐 Flutter／桥接／Android 验证，核对签名 Release 制品并记录实际支持与未验证边界。

验收：在实际 Android 环境中完成两个 App 访问同一 Host 的分流反例和修改闭环，不能只凭 mock 或规则文本放行。
识别、性能、数据缺口与已有功能回归有可复核结果；各项失败和跳过分别记录，不推定旧 Android 或其它平台已支持。
最终文档与实际交付一致，并按有效授权完成制品交付。
