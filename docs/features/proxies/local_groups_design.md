# Proxies 本地分组管理

保留订阅配置模式。自建分组归属当前 Profile，成员来自该 Profile 已加载且仍获许可的节点；切换 Profile 后展示对应分组。不汇总其它订阅节点，不新增独立节点模式。

## 体验修订（2026-11-09）

本轮按实际反馈修订交互。来源材料采用缓存优先：在当前声明、材料许可与来源绑定仍有效时，复用已保存节点材料并重新校验，不把配置快照失效等同于材料必须重新下载。显式更新和原自动更新机制仍负责新材料；来源撤回、变更或恢复标记不能通过缓存绕过。

返回 Proxies 时保留同一订阅的已有节点；临时 Core 状态读取失败不清空它们。准备状态只占一个稳定的提示区，不改变节点页面的挂载位置。显示“本地准备／来源准备／应用”等实际阶段，不把所有进度都称为下载。

分组编辑按“名称、切换策略、节点”分区，使用标题、组间留白和一致的容器。策略区使用“启用速度测试”开关，开启时显示测试 URL 输入框，关闭时隐藏；没有重复的策略副标题。切换开关保留地址草稿，有效地址随分组保存。关闭后仍使用原有按顺序故障转移策略；无效的隐藏草稿不阻止保存，故障检测继续采用该分组先前有效的地址。正则帮助只保留输入控件旁的图标按钮，点击打开 Go 官方文档。匹配结果默认全选，并允许取消／重新勾选；取消项随表达式保存，来源更新重新计算时继续排除它们。更换表达式重置这次排除，清空表达式恢复原手选状态。

管理列表将订阅组和自建组统一为紧凑行。用简短来源／状态区分，编辑、启停和删除收进自建组的操作菜单，不为每个自建组保留一个额外的大操作区域。使用分组是让现有路由入口指向该组，不是浏览组，也不是开启代理；入口和结果必须明确反馈，图标不冒充勾选状态。

分组编辑页保存先完成必要的本地校验及持久化，随后返回管理页；配置采用可在后台完成，显示已保存、正在应用或保存后未采用的结果。引用管理页则等待应用结果，成功后关闭。分组保存不应为了本地定义变化重新下载来源。应用失败后保留可修改、可重试的已保存定义，不把“已保存”伪装成“已生效”。

布局参考 [Android Settings](https://developer.android.com/design/ui/mobile/guides/patterns/settings) 的分区容器、简短状态与上下文操作，以及 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 的内容层级与一致布局原则；本节是本项目的具体交互设计。

## 页面和使用流程

Proxies 菜单提供“分组管理”和“管理分组引用”。管理列表直接展示自建与订阅分组，订阅分组标为只读，不默认折叠。自建组通过同一行右侧的操作菜单支持启用、禁用、编辑和确认删除。

点击列表中的分组进入展示页，显示成员和当前首选节点；若该节点仍是另一个组，同时显示解析后的实际出口。新增按钮或编辑按钮进入独立编辑页。编辑页只配置名称、切换策略、测速地址和成员，不再提供类型与父分组两个下拉框。旧的 Selector 定义继续兼容；进入编辑并保存后采用用户确认的新自动策略。

新建组独立保存。Proxies 或自建组菜单中的“管理分组引用”先选择一个自建组，再展示当前已加载配置中的目标 Selector 和已有引用，支持多选和取消。保存只修改可选成员，保留各目标当前选择。应用成功后关闭引用管理页；失败保留勾选并显示具体原因。页面没有 View group、Use now 或对应的跳转、主动切换操作。真正选用某个分组继续在 Proxies 的目标组中完成。

引用目标来自实际已加载配置，不按“默认节点”等名称猜测，也不改写原规则。GLOBAL 由 Core 自动提供可选成员，不保存为本地引用。同一自建组可被多个 Selector 引用；旧 parent 字段继续读取，新关系保存到 parents。当前正在被选择的引用不能直接取消，删除／禁用被使用的组也会被阻止；需先在 Proxies 选择其它成员，避免隐式切到 DIRECT 或首个节点。直连、规则和全局模式都可以管理这些引用，保存不会改变模式或启动代理。

## 策略与临时选点

新建组始终保留故障转移，“启用速度测试”开关选择策略：开启使用 URLTest，关闭使用 Fallback。默认关闭。不新增手工排序，顺序沿 Core 原有成员顺序。

展示页点选节点只影响当前运行。节点可用时使用它，检测到不可用后按该组策略迁移；迁移后不保留旧手选偏好。界面不提供取消或“恢复自动”。手选不写 Profile.selectedMap 或恢复检查点。原有 Selector 路由入口的选择仍正常保存，两种操作各自承担不同职责。

Fallback 沿用 Core 的故障检测与选点；URLTest 由当前配置拥有的轻量观察任务在手选节点失效后清除强制选择，任务不下载材料、不自行探测网络，配置退役或选择失效后结束。故障检测仍依赖 Core 的健康检查和请求失败反馈，不承诺单个失败请求会透明重放。已建立连接继续使用原套接字。

## 手选与正则

只提供手选和正则两种成员选择方式，没有分批添加：

- 表达式为空：展示全部节点及原手选状态。
- 表达式非空：展示全部匹配节点并默认全选，可继续取消或重新勾选；成员来自匹配结果减去手工排除项，不与手选列表合并。
- 修改表达式：替换预览并重置排除项。清空表达式：恢复全部节点和之前的手选状态。
- 语法错误：显示错误，阻止保存，不覆盖手选列表。显式保存要求有可用成员。

表达式采用 Go 标准库 [regexp](https://pkg.go.dev/regexp)，预览、校验和成员重新计算使用同一实现。编辑页提供其[官方语法文档](https://pkg.go.dev/regexp/syntax)跳转入口，不另写语法教程。用户表达式不直接交给 Core 的另一种过滤引擎；实际 provider 引用使用转义后的精确成员名称。

手选列表、表达式、完整匹配快照和手工排除项分别保存。来源更新获许可后重新计算匹配结果，并重新核验节点名称唯一性；新增来源或超出原维护许可的变化仍需审核。重新计算后零匹配的运行组使用 REJECT，不隐式直连。手选成员被删除或出现跨来源重名时拒绝采用有问题的新材料。

## 启动与更新

Android 界面重新打开时，若服务正在运行同一 Profile 且 Core 报告配置有效，直接接回状态并读取已有节点，避免强制重复准备整套配置。

运行中同一 Profile 的刷新和分组编辑优先走现有的热采用路径。先准备来源、校验材料，再采用支持的图变化；失败或结构不支持热采用时保留仍有效的旧配置，显示未采用状态。当前支持范围仍受 Core 的结构、并发读者和退役材料预算限制；不承诺所有设置变更都能热替换。旧材料失效或权限撤回时，仍遵守原有停止使用边界。

Proxies 保留已有节点展示，不用全局无限进度条覆盖它们；页面区分检查保存的配置、读取保存的来源文件、下载来源更新和应用配置；只有实际 HTTP 获取时显示下载，失败也会结束该状态。失败时提示保留旧配置或更新失败，并提供重试。Core 数据暂时读取失败不会清空同一 Profile 的已有节点。切换 Profile 时不把旧 Profile 的节点当成新 Profile 的可选成员。

## 保存、许可与并发

Profile.localGroups 随 Profile 持久化。数据库 schema 14 的 JSON 列继续使用，新增字段通过默认值兼容旧数据，不再新增数据库迁移。原订阅文件不重写，备份随 Profile 保存定义。

正常启动组合先执行原订阅／覆写，再追加启用的本地组和明确选择的入口引用。本地分组保存从 Core 当前仍有效的已审核输入生成差异，不重新读取远程订阅或启动审核。其它节点、规则、DNS、监听与 provider 声明保持原值。受管 Policy draft 沿用自身契约，不注入本地组。

沿用[来源接受设计](../security/source_acceptance_design.md)。本地保存只授权本次分组差异。Core 使用当前已接受输入作为基线，校验版本 fence、自己的有效提交凭据、节点材料与完整差异；不能通过保存组授予远程来源许可。provider 材料在新分组上下文重新核验，原材料和旧连接按已有退役机制保留。自动正则重新计算只采用当前已接受的本地表达式，不把新表达式当成自动授权。

较新的 Profile、设置、来源版本、模式或运行意图胜过旧操作。保存、配置采用、节点选择分别检查结果；保存失败保留表单。待审时仍可保存不增加启用范围的禁用／删除操作，并明确提示尚未采用。只有能证明新配置未采用且数据未被较新编辑取代，才回退本次保存。
