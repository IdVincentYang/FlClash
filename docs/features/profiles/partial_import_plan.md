# 关联来源部分失败的订阅导入 Plan

基线 3b56a77。修复 URL 导入把保存与完整来源审核绑定的问题；不推进应用网络的后续任务。

## 行为与边界

所有关联来源首次尝试结束之前，接受及降级操作均不可用。排队、下载、核验及重试均算未结束；
最终配置 Ready 只代表配置预览已解析，不表示全部关联材料可用，也不证明节点已经测速可达。
全部成功沿用完整接受；部分失败后提供独立的“保存待补齐”和“仅使用已加载节点”。

保存待补齐只限新 URL 导入：在原下载会话和当前性检查内保存未获许可的原材料，不接受来源、
不替换已有订阅、不应用配置。现有待审核状态及 Review source 提供后续补齐入口。

节点操作只采用原文及成功核验的节点来源里的内联节点，生成独立、确定的节点快照；
不保留源规则、分组、DNS、监听器、tunnels、外部来源或脚本；节点依赖不完整时不纳入。
形成一个可手选的节点组及显式 MATCH；仍走原来源材料、最终配置审核及正式提交路径。
同一导入窗口展示精简后的节点数量／路由／DNS，用户再次点击接受才保存，不将选择降级等同授权。
URL 保留，节点快照关闭自动更新；恢复完整内容使用正常更新并重新审核，不后台恢复源分流。应用自身网络设置保持既有权威。

## 实施与验证

先定义本方案，再调整加载终态与导入限定的替代决定；复用 RequestSession、SourceAcceptance、
原配置预览、材料提交、队列和来源状态。避免新增权限权威、数据库模式或后台下载机制。
有效契约更新 source_acceptance_design／guide、architecture；本轮验证写 partial_import_result。

测试覆盖早失败但其它来源仍排队／在途、全部结束、独立重试、无节点、节点依赖及重名、
保存待补齐无许可且不影响既有配置、精简节点二次审核／取消／保存／重启及恢复完整更新。
运行相关 widget、导入、来源／真实 Dart→Go 桥接、静态检查与生成器，构建 Android 调试包。
使用合成数据与本地服务，原始订阅和凭据不外发；提交、合入与普通推送沿既有授权。
